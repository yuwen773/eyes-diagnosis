# 15 — 将 Agent 业务写入统一接入用户确认

**What to build:** 用户通过聊天提出修改资料等受支持业务操作时，先查看具体变更并批准或拒绝，内部或 MCP 工具都不能绕过确认直接写入。

**Blocked by:** 11 — 实现正式诊断保存前的用户确认；14 — 迁移 MCP 工具选择并统一图像推理来源。

**Status:** ready-for-human（受控工程验证；真实 MySQL、Java/MCP 服务与部署验收另行执行）

**Spec:** Python Agent 迁移与眼底诊断工作流 Spec（2026-10-12）。

**Acceptance mapping:** AC-09、AC-10；本票完成所列判据的相关部分，不代表提前通过整个 spec。

- [x] 复用既有用户确认机制，至少打通一个已支持的资料变更操作，保持正式诊断保存同样受控。
- [x] 模型只能提出操作意图；服务端解析目标、检查权限和内容版本，未知或未登记的副作用工具不得按只读直接执行。
- [x] 聊天能展示拟修改内容并处理批准、拒绝和过期，不要求聊天记录、进度与审计逐条批准。
- [x] 用户决定只授权所见操作版本；角色、参数或工具变化导致原授权失效，跨用户批准被拒绝。
- [x] 重复确认、工具重试和图恢复最多产生一次业务变更效果，旧直接业务 API 不被静默改造。
