# 13 — 让聊天按需查询带来源的历史诊断

**What to build:** 用户在当前会话询问自己的既往诊断时，Agent 通过授权查询返回有来源的历史记录，且不会把历史症状当成本次病例事实。

**Blocked by:** 05 — 迁移普通聊天与当前会话记忆。

**Status:** ready-for-human — 2026-10-14；实现与受控验证完成，真实服务/模型验收待执行。见 `docs/history-retrieval.md` 与 `docs/history-retrieval-review.md`。

**Spec:** Python Agent 迁移与眼底诊断工作流 Spec（2026-10-12）。

**Acceptance mapping:** AC-02、AC-03；本票完成所列判据的相关部分，不代表提前通过整个 spec。

- [x] 从聊天触发服务端绑定用户的历史查询，支持现有已保存记录，不依赖新任务先保存一条记录。
- [x] 回答展示可追溯记录标识、时间与来源，明确历史和本次上下文边界。
- [x] 另一用户记录不能通过参数、提示词或工具调用读取。
- [x] 没有历史或查询失败时如实说明，不生成虚构记录；未按需查询时不自动载入所有会话资料。
- [x] 查询是只读操作，不生成诊断工作流或请求无必要的保存确认。
