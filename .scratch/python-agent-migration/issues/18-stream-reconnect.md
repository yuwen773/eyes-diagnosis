# 18 — 统一聊天和诊断事件并恢复断连界面

**What to build:** 用户在聊天与诊断页面看到一致的进度、补充信息、确认、复核与结束事件，断网或刷新后能从服务端恢复当前任务状态。

**Blocked by:** 10 — 完成最终临床复核与受限发布；12 — 补齐用户补充信息的暂停与恢复；15 — 将 Agent 业务写入统一接入用户确认。

**Status:** ready-for-agent

**Spec:** Python Agent 迁移与眼底诊断工作流 Spec（2026-10-12）。

**Acceptance mapping:** AC-14、AC-21；本票完成所列判据的相关部分，不代表提前通过整个 spec。

- [ ] 聊天 token、工具状态与工作流事件可关联会话、任务或操作，保留旧 SSE 正常结束和错误契约。
- [ ] 两个页面展示相同的等待/复核/批准/失败/完成状态，不把流结束等同于任务成功或正式记录已保存。
- [ ] 断流、刷新及重连后从服务端状态恢复，不重新推理、不重复写入，也不泄露其他用户事件。
- [ ] 患者界面只展示允许发布的解释和限制，不显示原始预测、内部路由或未校验草稿。
- [ ] 关键交互具有前端端到端回归，并通过类型检查与构建，保持现有品牌风格。

## Verification

用浏览器端到端主动断连/重连，结合真实 SSE 与状态 API 验证界面恢复及无重复业务效果。

## Constraints

只在迁移 worktree 实施，保留原 Java 源码与构建配置；Java 继续拥有三个会话端点。沿用 release 的业务 ADR、MySQL 单一业务事实来源与图决定路由。正式业务写入须用户确认，医生复核另行执行。测试模拟与真实服务结果必须区分。没有修改、删除或发布源 spec 的任务。
