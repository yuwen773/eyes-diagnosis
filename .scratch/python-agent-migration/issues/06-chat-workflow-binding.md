# 06 — 让聊天和上传页面共享诊断任务

**What to build:** 用户在聊天中发起或继续图片诊断，聊天与上传页显示同一个 Workflow 的标识、进度和结果，不各自产生一套诊断记录。

**Blocked by:** 02 — 跑通上传任务的持久执行最小闭环；05 — 迁移普通聊天与当前会话记忆。

**Status:** completed — 2026-10-13；实现与边界见 `docs/chat-workflow-binding.md`，双轴审查见 `docs/chat-workflow/issue06-review.md`。仅完成本票相关部分，不代表整个 spec 或真实模型验收完成。

**Spec:** Python Agent 迁移与眼底诊断工作流 Spec（2026-10-12）。

**Acceptance mapping:** AC-01、AC-14、AC-21；本票完成所列判据的相关部分，不代表提前通过整个 spec。

- [x] 聊天触发诊断经同一个工作流服务与幂等契约，不维护第二套推理流程。
- [x] 聊天会话、附件和 Workflow 建立受授权的关联；重复发送、刷新与查询不创建重复任务或重新推理。
- [x] 两个入口都能显示服务端进度与失败，不能将本地缓存视为任务完成。
- [x] 普通闲聊仍走聊天分支，自由文本不改变临床路由，模型不能指定内部下一节点。
- [x] UI 保留原风格和聊天方式，只增加任务关联与必要状态展示，并通过前端类型检查和构建。
