# 20 — 交付可复现部署、切流与回退演练

**What to build:** 维护者按交付说明启动所有服务，逐项切换业务与 Agent 路由，并能切回旧系统而不遗失任务或让两套 Worker 竞争执行。

**Blocked by:** 19 — 完成真实基础设施和旧接口兼容验收。

**Status:** ready-for-agent

**Spec:** Python Agent 迁移与眼底诊断工作流 Spec（2026-10-12）。

**Acceptance mapping:** AC-19、AC-20、AC-21；本票完成所列判据的相关部分，不代表提前通过整个 spec。

- [ ] 消除 Nginx 与 Java 端口冲突和代理回环，健康检查与鉴权转发均通过真实启动验证。
- [ ] 启动说明包含 Python 依赖、文档解析外部依赖、Worker、数据库升级与 Java 会话配置；原 Java 源码和构建配置不变。
- [ ] 业务接口切流、Agent 切流、数据库升级和执行器归属有明确步骤，回退不让新旧两套服务执行同一任务。
- [ ] 旧端不具备新工作流能力时保留 Python 的查询或安全排空路径，明确继续/暂停策略，不把改路由等同于完整回退。
- [ ] 演练中任务、待确认与复核记录不丢失；前端登录、上传、任务查看和聊天经过 Nginx 实测。
- [ ] 记录回退条件、恢复步骤及证据；不在本票中未经授权发布生产部署。

在隔离可复现环境演练数据库升级、全栈启动、分项切流和回退，保留任务与审批前后对照。
