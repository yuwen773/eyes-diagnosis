- [ ] 准备三类诊断数据和四类 Python 人工等待的合成样本定义，明确稳定 ID、归属、来源、批准与审计不变量；记录导出图及独立聊天补充版本的恢复约束。
- [ ] 基线准备阶段的独立契约/摘要检查可运行并报告差异；此阶段只扩展基线，不替换生产路径、不改原 Java/旧 SQL/历史 spec，也不将基线结果宣称为迁移完成。
- [ ] 初始化在无 JVM 环境执行，覆盖旧 SQL/callback 的必要效果和已确认 schema，原 SQL 字节与摘要不改变。
- [ ] 新迁移链使用独立历史；初始化、重复执行和后续增量升级行为明确，并发升级受控，不靠 API/Worker 启动时执行 DDL。

**Acceptance criteria:**

- [ ] 旧任务只读 API/UI 不要求 Python UploadInput 或当前图/checkpoint 绑定，能处理真实旧结构中的缺失字段，不反序列化执行 Java checkpoint。
- [ ] 查询以原 owner 归属鉴权，跨用户与匿名访问被拒绝，不因旧版缺字段绕过权限；医生/管理角色如需查看，沿用明确授权语义。
- [ ] 清楚区分传统已保存记录、旧版未完成任务和当前 Python 工作流；旧任务保留原状态、时间与来源，不伪装完成或可续跑。

**Verification:** 旧结构数据的 API/UI → 明确确认 → 幂等关联创建 → 独立 Worker；覆盖跨用户、重试、原输入缺失及新批准。
