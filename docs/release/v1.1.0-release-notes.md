## 中文

### 1. 版本概要

Iris v1.1.0 是 Iris 2.x 的第一个正式代码版本。相对上一个公开基线，它把三条并行推进的工程线收口到同一棵代码树：
**Iris 2.1 自适应视觉系统**、**诊断 Agent 的正确性与运行时护栏**、以及**多 Agent 协作的基础设施**（基础设施随版本发布，但生产开关默认关闭）。
本版本同时完成发版所需的工程治理：可复现构建、版本元数据、Flyway V18–V29 迁移链与单一 CI 工作流。

### 2. 主要更新

#### 2.1 Iris 2.1 · 自适应视觉系统（`web/`，产品前端）

- **四场景视觉体系**：Brand（首页 / 登录 / 注册 / 资讯）、Management（管理端）、Intelligence（Agent 工作区）、
  Clinical（判读 / 档案 / 个人中心）各有独立的密度、圆角、主色与材质规则，规则真源为仓库根 `DESIGN.md`，
  令牌实现为 `web/src/styles/tokens.css`。
- **双主题**：浅色 / 深色在根节点翻转，纸面原语冻结，含防 FOUC 的主题初始化。
- **品牌层**：光学虹膜标、首屏光学台、蓝光学玻璃背景与可访问的动效预算
  （含 `prefers-reduced-motion`）。
- **产品页面**：落地页、登录 / 注册、资讯列表与详情、判读工作区、档案与记录纸、个人中心、
  管理端六页工作台（Dashboard / 诊断 / 新闻 / 新闻编辑 / 知识库 / 用户）、Agent 三栏工作区与协作工作台（入口默认不显示）。
- **UI 冻结基线**：`iris-ui-v2.1-freeze-20261115` → `80f53f7f`（不移动）；品牌标记后续版本
  `iris-ui-v2.1.1-optical-20261116`。冻结范围内的一般视觉优化登记 Issue，不在基线上直接改。

#### 2.2 诊断 Agent（Spring AI + Spring AI Alibaba）

- **SSE 流式对话**：`/api/agent/chat/stream`，覆盖会话、历史与工具执行过程。
- **工具状态族收口**：`running / succeeded / failed / cancelled / awaiting-confirm` 由服务端唯一词表定义，
  同时驱动 SSE、前端状态与落库，避免前端自行推断。
- **工具结果闭环**：成功结果正文（脱敏 + 上限截断）与结构化资源随终态下发，并持久化；
  刷新页面后仍能恢复当时的工具结果与引用。
- **时间契约**：所有消息时间戳统一为带时区偏移的 ISO-8601，历史与实时消息不再出现时区错位。
- **统一脱敏**：推理正文、工具参数、工具输出、确认文案四个出口统一经过敏感信息脱敏。
- **运行时护栏**：工具调用预算按单次运行隔离，超预算时不再执行工具并记录为失败终态；
  图递归上限接线到配置项。
- **工具失败语义修复**：修复上游框架默认配置下「真实工具失败被记成成功」的问题，
  失败以明确的错误终态呈现，且不会中断整条会话流。
- **MCP 扩展**：用户可配置 STDIO / SSE / Streamable HTTP 三类 MCP 服务器，工具发现结果短期缓存；
  会话级覆盖优先于用户级启用 / 禁用。
- **外域图片保护**：前端只加载受控来源的会话影像，防止远程图片绕过授权。

#### 2.3 视觉分析与影像

- **视觉工具**：`EyeImageAnalyzerTool` 通过 DashScope **Qwen-VL-Plus** 对眼底图像做视觉分析，
  与诊断 Agent 的工具调用链集成。
- **影像上传与归属**：Agent 上传的影像按用户前缀隔离，登记上传状态，失败有补偿与清扫路径；
  历史附件按**当前用户**逐张复核归属后才恢复成附件。
- **判读影像与患者任务**：眼底判读、患者影像任务、分层解释与随访链路随 V18–V24 迁移一并发布。

#### 2.4 知识库 RAG

- **处理链路**：文档解析（PDF / MD / TXT / DOCX）→ 分块 → DashScope 嵌入 → ChromaDB 检索。
- **检索增强**：默认启用向量检索 + BM25 混合检索（RRF 融合）与 `gte-rerank-v2` 重排；
  检索参数（top-k / final-top-k / 相似度阈值）可配置。
- **索引版本准入**：每次文档处理生成服务端索引版本（V29 `indexVersion`），检索只认「已就绪 + 当前版本」的片段；
  失败代、旧代与清理残留不会成为来源。
- **来源标记策略**：`rag.source-type.enabled` 默认关闭，开启后只会**收窄**可见集合，不扩大默认可见性。
- **内置语料播种**：`rag.corpus.seed-enabled` 默认关闭（播种会产生嵌入费用）。

#### 2.5 多 Agent 协作基础设施（默认关闭）

本版本包含协作运行所需的**基础设施与工作台**，但前后端生产开关均默认关闭，发布不等于启用：

- 持久领域事件（V25）、图执行与检查点（V26）、运行归属与租约、授权快照、SSE 订阅与取消；
- 协作运行接口 `/api/agent/collaboration-runs/*`；
- 前端协作工作台入口由构建期变量 `VITE_COLLABORATION_ENABLED` 控制，未设置时不显示。

启用需要**同时**打开 `eye-diagnosis.collaboration.*` 与构建期变量，并配置协作游标密钥；
任一侧未开启时该能力不可用。本版本不做临床启用，也不部署。

#### 2.6 工程架构与可复现构建

- **版本元数据**：`pom.xml` 由 `0.0.1-SNAPSHOT` 升为 `1.1.0`；`web/package.json` 与锁文件根版本同步为 `1.1.0`。
- **可复现构建**：固定 `project.build.outputTimestamp`，同一环境两次 `clean package` 的 JAR **逐字节一致**，
  SHA-256 见文首表格。前端由 `npm run build`（`tsc -b && vite build`）产出，CI 负责类型检查、单测、Lint 与构建。
- **迁移链**：V18–V27 为多 Agent / 协作 / 患者任务线的整合迁移，V28 新增工具审计表，V29 新增知识索引版本；
  已应用迁移不修改，历史路径见 `docs/architecture/migration-matrix.md`。
- **单一 CI 工作流**：`.github/workflows/verify.yml` 同时覆盖编译、后端单测、MySQL 集成门禁、
  Flyway、Python、watchdog、文档契约、前端单测 / Lint / 构建与 Playwright 浏览器契约。
- **后端全量验证**：`scripts/verify.sh` 自带一次性 MySQL 8 + Redis，跑完整 `mvn test` 后自动清理。
- **双后端线约定**：`master` 为 Java 线，`feature/python-backend` 为 Python 线，两条线不再互相合并，
  共享目录改动需人工搬运（见 `docs/backend-split.md`）。

#### 2.7 安全改进

| 改进 | 内容 |
|---|---|
| 同源校验 | 所有状态变更方法（POST / PUT / DELETE / PATCH）校验 `Origin` / `Referer`，缺失也不放行；拒绝体与统一响应同形 |
| 密码存储 | 新密码 BCrypt cost 12；历史 MD5 账号在登录成功时即时升级 |
| 敏感信息脱敏 | 推理、工具参数、工具输出、确认文案四个出口统一脱敏 |
| 附件可信性 | 附件身份存在客户端不可写的服务端字段；历史读取按当前用户逐张复核；上传接口只返回受保护取图路径 |
| 上传状态机与补偿 | 上传状态可追踪，失败有补偿删除与定时清扫，避免孤儿对象与误删被引用对象 |
| 工具审计 | V28 新增独立审计表（默认关闭持久化）；开启需配置摘要密钥 |
| 落库失败语义 | 用户消息写入失败直接报错（fail-closed），不假装「已受理」；工具终态先提交再发送 |
| 可视化状态 | 工具失败、超时、取消、预算终止都有明确终态与用户可见说明，不渲染成成功 |

### 3. 破坏性变更与升级注意

1. **版本号语义变化**：`0.0.1-SNAPSHOT` → `1.1.0`。产物文件名变为 `eye-diagnosis-1.1.0.jar`；
   任何写死旧文件名的本地脚本需同步修改（本版本已更新仓库内一处证据脚本说明）。
2. **数据库升级（V17 → V29）**：需要执行 V18–V29。对既有表只有两处加列：
   V22 给 `t_diagnosis` 加可空 `patientTaskId`，V29 给 `t_knowledge_document` 加可空 `indexVersion`。
   空库直接启动即可；history 含 V10–V14 的旧 Java 线库需按迁移矩阵重建，不能用 `repair` 掩盖。
3. **知识库文档需要重新处理**：历史文档 `indexVersion` 为 NULL，在版本准入检索里视为「不能证明处理完整」。
   升级后需重新处理要保留的文档并验收检索结果。
4. **前端需重建**：旧前端 + 新后端可用；新前端 + 旧后端会缺少端点。生产部署时必须重新构建 `web/`。
5. **反向代理必须保留 Host**：同源校验按请求实际 Host 比对，Nginx 等反代需
   `proxy_set_header Host $host`（并保留 Origin / Referer），否则所有 POST 会被 403（`CROSS_ORIGIN_BLOCKED`）。
   本版本不通过全局放宽校验来适配反代；如域名与后端 Host 不一致，可显式配置 `security.same-origin.additional-hosts`。
6. **Java 线 / Python 线不互相合并**：本版本只发布 Java 线（`master`）。

### 5. 已知限制

1. **临床能力未经验证**：本版本是工程版本，不是医疗器械或临床产品。未在真实临床数据上做疗效或安全性评估；
   所有临床相关生产开关保持关闭，界面措辞保留「模型推理 ≠ 医学证据」口径。
2. **对象存储是过渡方案**：当前使用腾讯云 COS。对象级私有化、短时签名视图与历史对象 ACL 回填**不在本版本内**
   （相关 PR #124 未合并）；未来计划迁移到自建 S3 兼容存储，在迁移完成前应把对象存储视为过渡性依赖。
3. **外部集成证据不完整**：DashScope → SSE 全链路、视觉工具成功路径与真实对象存储上传的端到端证据
   尚未形成可独立核验的归档；相关状态以 `docs/release/release-candidate-readiness.md` 与
   `docs/release/verification-matrix.md` 为准。外部集成跑通**不等于**临床能力通过。
4. **工具审计摘要密钥**：开启 `agent.tool-audit.enabled=true` 时必须显式设置 `AGENT_TOOL_AUDIT_DIGEST_KEY`；
   未设置时会回退到仓库内置的开发默认值，本版本**不会因此启动失败**（已登记为后续修复项）。
5. **存量知识文档全量重处理没有入口**：需要人工逐文档重新处理。
6. **停止生成不打断已入队的写入**：取消只停流，已排队的消息仍按会话顺序提交，以免历史缺终态。
7. **Vue 前端已弃用**：`frontend/` 仅保留可运行以作回溯，不再作为设计参考，新功能一律进 `web/`。
8. **UI 冻结**：冻结范围内不做主动视觉迭代；阻断性故障与安全修复除外。

## English

### 1. Overview

Iris v1.1.0 is the first formal source release of the Iris 2.x line. It consolidates three parallel workstreams into one tree:
**the Iris 2.1 adaptive visual system**, **diagnosis-agent correctness and runtime guardrails**, and the
**multi-agent collaboration infrastructure** (shipped, but disabled by default in production).
The release also adds the engineering groundwork: reproducible builds, version metadata, the Flyway V18–V29 migration chain,
and a single CI workflow.

### 2. Highlights

#### 2.1 Iris 2.1 · Adaptive Visual System (`web/`, product frontend)

- **Four experience scenarios** — Brand (landing / auth / news), Management (admin), Intelligence (agent workspace),
  and Clinical (diagnosis / records / profile) — each with its own density, radius, accent and material rules.
  The normative spec is `DESIGN.md`; the implemented tokens are `web/src/styles/tokens.css`.
- **Dual theme** with root-level switching, frozen paper primitives, and FOUC-safe initialization.
- **Brand layer**: optical iris mark, optical hero, blue-glass background, and a motion budget that respects
  `prefers-reduced-motion`.
- **Product pages**: landing, login/register, news list and detail, diagnosis workspace, records and record sheet,
  profile, six admin pages, the three-column agent workspace, and the collaboration workspace (entry hidden by default).
- **UI freeze baseline**: tag `iris-ui-v2.1-freeze-20261115` → `80f53f7f` (immutable); the optical brand mark follows in
  `iris-ui-v2.1.1-optical-20261116`.

#### 2.2 Diagnosis Agent (Spring AI + Spring AI Alibaba)

- **SSE streaming chat** at `/api/agent/chat/stream`, with sessions, history, and tool execution visibility.
- **Single tool-state vocabulary** (`running / succeeded / failed / cancelled / awaiting-confirm`) driving SSE,
  the UI, and persistence — no client-side guessing.
- **Closed-loop tool results**: redacted and size-capped output plus structured resources are streamed on the terminal
  frame and persisted, so a page refresh restores what actually happened.
- **Time contract**: every message timestamp is ISO-8601 with an explicit offset; live and historical messages agree.
- **Unified redaction** across reasoning text, tool arguments, tool output, and confirmation copy.
- **Runtime guardrails**: a per-run tool-call budget that records failures instead of fake success when exhausted,
  plus a configurable graph recursion limit.
- **Tool failure semantics fix**: upstream defaults could classify a genuinely failed tool as success; failures now
  surface as explicit error states without aborting the stream.
- **MCP extension**: user-configured STDIO / SSE / Streamable HTTP servers, cached tool discovery, and session-level
  override precedence.
- **Foreign-image protection**: the client only loads session images from controlled sources.

#### 2.3 Vision analysis and imaging

- **Vision tool**: `EyeImageAnalyzerTool` calls DashScope **Qwen-VL-Plus** and is wired into the agent tool loop.
- **Upload ownership**: agent uploads are isolated per user, tracked by an upload state machine, with compensation and
  cleanup paths; historical attachments are restored only after a per-user ownership re-check.
- **Diagnosis imaging and patient tasks**: diagnosis, patient tasks, layered explanations, and follow-up flows ship with
  the V18–V24 migrations.

#### 2.4 Knowledge-base RAG

- **Pipeline**: document parsing (PDF / MD / TXT / DOCX) → chunking → DashScope embeddings → ChromaDB retrieval.
- **Retrieval**: vector search plus BM25 hybrid retrieval (RRF fusion) and `gte-rerank-v2` reranking, all enabled by
  default and configurable (top-k, final-top-k, similarity threshold).
- **Index-version admission**: each processing run gets a server-side index version (V29 `indexVersion`); retrieval only
  accepts chunks that are ready and at the current version. Failed, stale, or cleanup-residual chunks never become sources.
- **Source-type policy**: `rag.source-type.enabled` is off by default; enabling it only narrows the visible set.
- **Built-in corpus seeding**: `rag.corpus.seed-enabled` is off by default (seeding incurs embedding cost).

#### 2.5 Multi-agent collaboration infrastructure (disabled by default)

The release contains the infrastructure and workspace, but **shipping is not enabling**: backend
`eye-diagnosis.collaboration.*` and the build-time `VITE_COLLABORATION_ENABLED` flag are all off/unset, and the
cursor key must be configured before enabling. Persistent domain events (V25), graph execution and checkpoints (V26),
run ownership and leases, authorization snapshots, SSE subscription/cancellation, and
`/api/agent/collaboration-runs/*` are present. No clinical enablement or deployment is part of this release.

#### 2.6 Engineering and reproducible builds

- **Version metadata**: `pom.xml` moves from `0.0.1-SNAPSHOT` to `1.1.0`; `web/package.json` and the lockfile root
  version follow.
- **Reproducible build**: `project.build.outputTimestamp` is pinned; two clean `package` runs produce byte-identical
  JARs. The SHA-256 is recorded at the top of this document. The frontend is built with `npm run build`
  (`tsc -b && vite build`), with type-check, unit tests, lint and build enforced in CI.
- **Migrations**: V18–V27 integrate the collaboration / patient-task lines, V28 adds the tool-audit table, V29 adds the
  knowledge index version. Applied migrations are never edited; see `docs/architecture/migration-matrix.md`.
- **Single CI workflow**: `.github/workflows/verify.yml` covers compilation, backend unit tests, MySQL integration gates,
  Flyway, Python, watchdog, documentation contracts, frontend unit/lint/build, and Playwright browser contracts.
- **Full local verification**: `scripts/verify.sh` provisions disposable MySQL 8 + Redis, runs the full `mvn test`,
  and tears everything down.
- **Two backend lines**: `master` is the Java line; `feature/python-backend` is the Python line. They are not merged
  into each other; shared directories are ported manually (`docs/backend-split.md`).

#### 2.7 Security improvements

| Area | Change |
|---|---|
| Same-origin enforcement | All state-changing methods (POST/PUT/DELETE/PATCH) require a matching `Origin`/`Referer`; a missing header is rejected, not allowed. The rejection body matches the unified response envelope. |
| Password storage | New passwords use BCrypt cost 12; legacy MD5 accounts are upgraded on successful login. |
| Redaction | Reasoning, tool arguments, tool output, and confirmation copy pass through one redactor. |
| Attachment trust | Attachment identity lives in a server-only field; history re-checks ownership per user; uploads return a protected image path. |
| Upload state machine | Trackable upload states with compensation deletes and scheduled cleanup, avoiding orphaned objects and deleting referenced ones. |
| Tool audit | V28 adds a dedicated audit table (persistence off by default); enabling it requires a digest key. |
| Failure semantics | Failed user-message persistence is a hard error (fail-closed); tool terminal states are committed before they are sent. |
| Visible states | Tool failure, timeout, cancellation and budget exhaustion all have explicit terminal states and user-facing copy. |

### 3. Breaking changes and upgrade notes

1. **Version semantics** change from `0.0.1-SNAPSHOT` to `1.1.0`; the artifact is `eye-diagnosis-1.1.0.jar`.
   Local scripts that hard-code the old filename must be updated (one evidence-script reference is updated here).
2. **Database upgrade (V17 → V29)**: apply V18–V29. Only two changes touch existing tables: V22 adds nullable
   `patientTaskId` to `t_diagnosis`, and V29 adds nullable `indexVersion` to `t_knowledge_document`.
   Empty databases migrate directly; old Java-line databases with V10–V14 history must be rebuilt per the migration
   matrix — do not use `repair` to mask them.
3. **Knowledge documents need reprocessing**: historical rows have `indexVersion = NULL` and are therefore not admitted
   as sources. Reprocess the documents you want to keep and verify retrieval afterwards.
4. **Rebuild the frontend**: old frontend + new backend works; new frontend + old backend misses endpoints.
   Production deployment must rebuild `web/`.
5. **Reverse proxies must preserve the Host header**: the same-origin check compares against the request Host, so Nginx
   needs `proxy_set_header Host $host` (and must forward Origin/Referer), otherwise every POST returns 403
   (`CROSS_ORIGIN_BLOCKED`). This release does not weaken the check globally; use
   `security.same-origin.additional-hosts` when the public host genuinely differs.
6. **Java/Python lines do not merge**; this release is the Java line (`master`) only.

### 5. Known limitations

1. **Clinical capability is unverified.** This is an engineering release, not a medical device or clinical product.
   No efficacy or safety evaluation on real clinical data has been performed, and all clinical production switches
   remain off. The UI keeps the "model inference is not medical evidence" wording.
2. **Object storage is transitional.** The project currently uses Tencent Cloud COS. Object-level private ACLs,
   short-lived signed views, and historical ACL backfill are **not** part of this release (PR #124 is unmerged).
   Migration to self-hosted S3-compatible storage is planned; until then COS is a transitional dependency.
3. **External-integration evidence is incomplete.** End-to-end evidence for the DashScope → SSE path, the vision-tool
   success path, and real object-storage upload is not yet independently verifiable. Status lives in
   `docs/release/release-candidate-readiness.md` and `docs/release/verification-matrix.md`.
   Passing external integration does **not** imply clinical validation.
4. **Tool-audit digest key**: enabling `agent.tool-audit.enabled=true` requires
   `AGENT_TOOL_AUDIT_DIGEST_KEY`. Without it the service falls back to a repository-public development key and
   **does not fail at startup** in this release (logged as a follow-up fix).
5. **No bulk reprocessing entry** for legacy knowledge documents; they must be reprocessed individually.
6. **Stop-generation does not abort queued writes**; cancellation stops the stream, and already-queued messages commit
   in session order so history never loses a terminal state.
7. **The Vue frontend is deprecated**; `frontend/` is kept only for traceability and is not a design reference.
8. **UI freeze** is in effect for the frozen surfaces; only blocking defects and security fixes are accepted there.
