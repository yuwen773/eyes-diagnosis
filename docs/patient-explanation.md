# 患者分层解释与安全协作进度（#21）

对应 [#21](https://github.com/yuwen773/eyes-diagnosis/issues/21)，沿用 [#15](https://github.com/yuwen773/eyes-diagnosis/issues/15) 的患者解释定义。患者首先查看主要信息、风险及下一步，再展开依据、不确定性和适用限制。模型预测并非确诊，医生复核与患者保存授权相互独立。

## 读取门禁

每次读取解释及引用，都须验证登录用户拥有任务。医生、管理员和资料审核人员不会因角色获得其他患者的读取权限。

医生批准是必要条件。读取还须匹配批准时的冻结任务、输入、推理、草稿、证据和协作材料，并持锁重新检查精确引用的当前来源资格及版本。来源撤回或材料变化后停止展示，不修改历史医生决定，也不生成新草稿或替换引用。

## 安全进度

患者工作说明来自后端固定文案，仅说明图像分析、受控资料检索、解释整理和一致性检查等业务阶段。模型输出、内部提示、协作上下文、历史异议、医生意见及未获准的疾病推测均不作为进度文本。

质量失败、模型拒识、证据不足及等待医生时，只显示允许的状态及行动提示。未知状态默认受限，不视为正常结果。现有任务列表和状态接口继续保持安全投影。

## 展示边界

获准结果以纯文本展示；引用只展示本任务冻结且当前仍有效的来源及精确片段，不提供原文件下载、内部对象地址或任意文档读取。切换账号、切换任务和重新读取时清理已有材料；读取失败时关闭旧结果，避免继续展示失效内容。

本任务不自动保存正式诊断记录，不增加追问流程，也不改变现有聊天和普通诊断入口。真实模型、领域审核、临床及生产验收须单独记录，合成工程验证不替代这些验收。

## HTTP 接口

接口沿用 `BaseResponse`，响应设置 `Cache-Control: no-store`。下表路径带 `/api` 前缀。

| 方法与路径 | 内容 |
|---|---|
| `GET /diagnosis-tasks/{id}/explanation` | 本人任务的 `taskId/status/stage/message/workNotes/result`；未放行时 `result=null` |
| `GET /diagnosis-tasks/{id}/citations/{index}` | 本任务获准结果中的零起始引用；每次重走完整读取门禁 |

解释可见状态为 `AVAILABLE`，其余为 `PROCESSING`、`WAITING_REVIEW`、`RESTRICTED`。既有列表与状态接口不增加敏感字段，批准后的任务仍使用原安全状态；是否可读结果由解释接口独立决定。不存在、非本人任务、未放行或越界引用返回业务 `40400`，未登录返回 `40100`。

放行结果包含六个区段的声明与逐声明引用映射、冻结来源片段及版本、模型和预处理版本，以及固定的模型预测和概率限制提示。来源作为纯文本展示，避免将不受信任的来源字符串变成可执行链接。没有新增迁移，不改变历史医生决定。

## 验证

用户确认从患者任务 HTTP API 与患者页公开交互验证，使用隔离 MySQL、合成资料和受控身份。专项 `PatientExplanationApiTest` 共 37 项；设置测试专用 `ISSUE21_TEST_URL=jdbc:mysql://127.0.0.1:<port>/issue21_test`（用户及密码为合成测试账号 `issue21`）后运行 `mvn -Dtest=PatientExplanationApiTest test`，再运行 `python scripts/check_surefire_skips.py target/surefire-reports issue21`。该数据库仅供本专项使用，套件会清空相关表。

未设置专项环境变量时测试明确跳过，不算验收通过。CI 的 `issue21-mysql` 作业要求完整例数与零跳过。工程范围、全量与浏览器证据见 [本次验收记录](testing/2026-11-09-issue21-patient-explanation-acceptance.md)。
