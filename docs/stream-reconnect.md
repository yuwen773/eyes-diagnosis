# 工单 18：聊天与诊断状态恢复

实施工作树：`py-rewrite`；日期：2026-10-14。

## 接口与界面行为

- 新增 `GET /api/diagnosis/workflows/{workflowId}/events`。一次请求返回一个 `event: state` 权威快照，然后以原有 `event: done` 结束传输。快照包含患者任务投影、关联补充说明、当前保存确认及已保存回执。
- 两个页面使用同一 `useUploadWorkflow` 与 `WorkflowStatus`，每次快照完成后间隔 1.5 秒继续读取。任务结束后仍读取，因为补充说明和用户确认可独立变化。网络错误自动重试，保留并标明上次确认的状态；401/403/404 清除任务数据，停止该任务自动查询。
- 每次 GET 都重新经过 Java 身份校验和任务归属校验。响应使用 `private, no-store`；查询不会启动 Worker、调用模型、重放聊天消息或批准任何操作。患者结果沿用既有解释发布校验；患者界面移除了图节点列表。
- 聊天 token 和工具状态携带 `sessionId`、`runId`，与历史执行记录关联；前端拒绝不匹配会话的事件并展示工具进度。原有正常 `done` 和失败 `error` 契约保留。
- 聊天在发送前保存会话标识。连接异常时读取已持久化历史；刷新、网络恢复和仍在运行的聊天查询均通过 GET 恢复。部分 token 不会被当作完整回答，也不会自动重发 POST。
- 补充说明、临床复核、任务完成和正式保存分别展示。诊断页与聊天页可同步恢复其他标签页提交的保存状态；丢失批准回执后仍以服务端回执为准。任务访问失效会触发聊天历史校验，清除未授权的消息和补充表单。
- 资料变更确认定期只读刷新，正在读取时不会叠加轮询；读取失败清除旧操作预览。用户决定仍使用原有确认版本和幂等约束。

这是有界 SSE 状态快照，不提供逐 token 的持久化重放。已中断且未提交的回答显示未完成；已提交但回执丢失的回答从历史恢复。没有修改临床图、Java 会话端点、Java 源码、Maven 配置或源 spec，也没有新增数据库迁移。
