# 眼疾诊断 AI 系统 — 知识库使用指南

## 1. 系统概述

知识库是本系统的 **RAG（检索增强生成）** 核心组件。它允许用户上传医学文档（眼科疾病资料、诊断标准、治疗指南等），系统自动解析、切片、向量化后存入 ChromaDB 向量数据库。当 AI Agent 进行智能对话时，可通过相似度检索召回相关文档片段作为上下文，显著提升回答的准确性与专业性。

## 2. 技术架构

```
用户上传文件（PDF/Word/TXT/MD）
        │
        ▼
┌───────────────────────┐
│  KnowledgeBaseService │  ← Controller 接收 multipart 请求
└───────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│  DocumentProcessingService     │
│  (ETL 异步处理流水线)           │
└─────────────────────────────────┘
        │
   ┌────┴────────────────────┐
   │ 1. Extract（抽取）      │
   │   └─ DocumentParser     │  ← Apache Tika 解析各类文档
   │                        │
   │ 2. Transform（转换）    │
   │   ├─ 文本合并           │
   │   ├─ Metadata 构建      │
   │   └─ TextChunkerService │  ← 512 词滑动窗口分块（重叠 100 词）
   │                        │
   │ 3. Load（加载）        │
   │   └─ VectorStore        │  ← Spring AI ChromaDB VectorStore
   └─────────────────────────┘
        │
        ▼
┌───────────────────────┐
│  ChromaDB (向量数据库)  │
│  :8000                 │
└───────────────────────┘
```

## 3. 支持的文件格式

| 格式 | MIME 类型 | 解析方式 |
|------|----------|---------|
| PDF | `application/pdf` | Apache Tika |
| Word (.doc/.docx) | `application/msword` | Apache Tika |
| 纯文本 (.txt) | `text/plain` | 直接读取 |
| Markdown (.md) | `text/markdown` | 直接读取 |

## 4. 存储结构

### 4.1 MySQL — `t_knowledge_document` 表

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键 |
| `userId` | BIGINT | 上传用户 ID |
| `title` | VARCHAR(255) | 文档标题（可自定义） |
| `fileName` | VARCHAR(512) | 原始文件名 |
| `fileUrl` | VARCHAR(1024) | 腾讯 COS 存储路径 |
| `fileSize` | BIGINT | 文件大小（字节） |
| `fileType` | VARCHAR(32) | 文件类型标识 |
| `contentHash` | VARCHAR(64) | SHA-256 内容哈希（用于去重） |
| `chunkCount` | INT | 向量化分块数量 |
| `status` | TINYINT | 处理状态：0=处理中, 1=已完成, 2=失败 |
| `createTime` | DATETIME | 上传时间 |
| `isDelete` | TINYINT | 逻辑删除标记 |

### 4.2 ChromaDB — 向量集合

- **Collection 名称**：`documents`（在 `application-dev.yml` 中配置）
- **Chunk ID 格式**：`doc_{docId}_chunk_{index}`
- **Metadata 字段**：`source`、`title`、`fileType`、`timestamp`、`contentHash`、`docId`

### 4.3 分块策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `chunk-size` | 800 词 | 每个文本块的目标大小 |
| `chunk-overlap` | 100 词 | 块间重叠字数（保留语义连续性） |
| 分隔符 | `\n\n`（双换行） | 按段落分割，空行超过 20 字符的段落才保留 |

## 5. API 接口

### 5.1 上传文档

```
POST /api/knowledge/upload
Content-Type: multipart/form-data
Authorization: 已登录用户
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `files` | MultipartFile[] | 是 | 文件列表（支持多文件） |
| `title` | String | 否 | 文档标题（默认使用原文件名） |

**成功响应**：
```json
{
  "code": 0,
  "data": [1, 2, 3],   // 上传成功的文档 ID 列表
  "msg": "success"
}
```

### 5.2 文档列表（分页）

```
POST /api/knowledge/list/page
Content-Type: application/json
Authorization: 已登录用户
```

```json
{
  "current": 1,
  "pageSize": 10
}
```

### 5.3 删除文档

```
DELETE /api/knowledge/delete
Authorization: 已登录用户
```

```json
{
  "id": 1
}
```

> 删除时同步从 ChromaDB 中移除对应所有向量块。

## 6. 前端使用流程

1. 进入 **管理后台 → 知识库管理**
2. 点击上传区域或拖拽文件（支持多文件批量上传）
3. 点击「开始上传」，系统上传至 COS 并触发异步 ETL 处理
4. 页面实时轮询（3 秒间隔）文档状态：
   - 🟡 **处理中** — 正在解析并向量化
   - 🟢 **已完成** — 可用于 AI 对话检索
   - 🔴 **失败** — 可重新上传或删除
5. 支持分页查看、单个删除

## 7. 在 AI 对话中触发检索

AI Agent 在对话中可调用 `DocumentSearchTool`（MCP 工具）从 ChromaDB 检索相关文档片段：

- **检索方式**：向量相似度搜索（余弦相似度）
- **召回数量**：默认召回 Top-K 相关片段
- **注入位置**：作为 `user` 消息的 `context` 附加给 AI 模型

用户在管理后台开启 MCP 服务器后，知识库内容即可被 AI Agent 自动利用。

## 8. 运维配置

### 8.1 相关配置项（application-dev.yml）

```yaml
spring:
  ai:
    vectorstore:
      chroma:
        collection-name: documents   # ChromaDB collection 名称
        url: http://localhost:8000     # ChromaDB 地址

eye-diagnosis:
  rag:
    chunk-size: 800                  # 分块大小（词）
    chunk-overlap: 100               # 分块重叠（词）
```

### 8.2 启动依赖

```bash
# 启动 ChromaDB 向量数据库
docker-compose up -d chroma
```

## 9. 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 上传后一直是"处理中" | ETL 异步任务失败或 ChromaDB 未启动 | 检查 ChromaDB 容器状态，查看后端日志 `[ETL]` 标记 |
| 文档"处理失败" | 文件格式不支持或内容为空 | 确认文件格式为 PDF/Word/TXT/MD，文件非加密或损坏 |
| AI 对话未召回知识库内容 | 未开启 MCP 服务器或知识库文档未处理完成 | 在 MCP 服务器配置中启用 DocumentSearchTool，确保文档状态为"已完成" |
| 上传提示"文档已存在" | 相同内容的文件已被上传（SHA-256 去重） | 系统根据内容哈希去重，可删除原文档后重新上传 |
