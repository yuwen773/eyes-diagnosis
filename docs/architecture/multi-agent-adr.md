# 实时多 Agent：运行时验证与事件边界

日期：2026-11-11。范围：实施计划 v1.1 的 TASK-01。状态：隔离 SPIKE 已实施；正式执行器迁移与 M0 整体验收待完成。

基线：[实施计划 v1.1](../plans/EyesDiagnosis_RealTime_MultiAgent_Implementation_Plan_v1.1.md)。能力与测试证据见 [TASK-01 报告](../testing/2026-11-11-realtime-graph-spike.md)。

## 决策

保留 Spring AI Alibaba `1.1.2.2`，不改 BOM。四角色候选图使用框架原生并行汇合、条件边和检查点；测试只替代外部模型响应，不替代框架。现有 Coordinator、角色契约和医学安全门禁保持原状。

先由现有 Coordinator 建立持久领域事件与 SSE，再迁移 Graph。Graph 只承担编排；运行归属、调用预算、取消、引用校验、事务提交及医生复核仍由应用与领域层负责。不得因 SPIKE 通过删除原有守卫。

状态字段显式声明 key strategy。SPIKE 的各角色写独立键，以 ReplaceStrategy 保存单值版本；不能从这一结果推定任意共享集合的并发合并安全。后续新增共享键时必须选择并测试对应 reducer。检查点中的版本须与已提交领域状态核对，不能覆盖较新的业务结果。

框架节点流可提供真实增量，但并行分支的普通 NodeOutput 在汇合后聚合。生命周期 before/after 可观察单分支实际执行；其中并行 after 的 state 是合并前快照，且监听器异常不能阻止执行。监听器适合进度观察，校验与提交必须置于节点/领域事务内；不能据其直接发布临床结果或确认持久事件。

SSE 与执行生命周期分离。框架订阅取消在本次测试路径阻止了后续节点，但未停止在途外部替身，也未阻止迟到生命周期回调。正式后端仍须持久取消意图、原子提交判定及 fencing；浏览器断线不应取消后台任务。

流完成不是业务成功。框架递归上限可以结束流而没有 END 和 Critic 成功结果；应用需检查合法终态和领域提交，单独记录停止原因。SPIKE 中的枚举和反馈上限检查只是测试适配策略，不是现有医学门禁的替代实现。

执行、医生审核和患者发布许可继续分开。REVIEW_READY 不是患者可见许可；run.completed 不由 Reactor onComplete 自动生成。原有影像绑定、精确引用、来源复验、医生批准和患者保存授权均保留。
