**一、任务目标与验证范围**

本次目标是验证现有 Vision、Evidence、Explanation、Critic 四个角色是否实际调用模型、传递同一任务的材料、执行检索与引用校验，并形成可供医生复核的冻结草稿。前期核对过上游数据和 OOD 限制；按用户明确要求，本轮四 Agent 验证以合成上游输入独立开展，没有等待缺失材料补齐。

执行的是当前产品代码 `PatientDraftCoordinator`、`DraftAgents`、`ControlledEvidenceRetriever`，使用真实隔离 MySQL 和真实 `qwen3.5-plus` 服务。基点提交为 `74cf7d8246c6fb30ad58bd0497f8e08f94be749f`，工作区存在未提交改动；核心四 Agent 产品源码摘要已记录并核对。

四 Agent 是共享同一个模型服务、具有各自提示词和上下文的四个独立角色调用。本轮不涉及四种不同基础模型，也未验证它们在医学效果上优于单 Agent。

上游使用合成推理快照，检索使用隔离库中的合成资料资格夹具。夹具通过测试初始化满足检索资格，不代表资料已经过真实医学来源审批。没有发送真实患者资料，没有执行真实图片到四 Agent 的完整流程。

**二、四个角色实际承担的工作**

| 角色 | 输入与职责 | 本轮核验重点 |
|---|---|---|
| Vision | 读取已有推理快照，总结预测信息、质量限制与再分析建议 | 不重新看图或运行图像模型；输出传给后续角色 |
| Evidence | 根据推理信息与 Vision 摘要生成查询，服务端检索受控资料 | 使用真实检索器，冻结证据版本；模型不能改写来源资格 |
| Explanation | 根据推理与冻结证据生成分层说明草稿 | 六个区段齐全，每条声明有引用，quote 必须匹配连续原文 |
| Critic | 检查实际冻结草稿、证据和推理之间的问题 | 可返回无异议、补证或重写；不能代替医生批准 |

运行预算保持为每任务最多 8 次调用、总时限 90 秒、单次时限 20 秒。未修改产品提示词、协调器、引用门禁或预算。

**完整成功场景：合成标签 `cataract`。** taskId 为 `aa36c409-a36b-4c41-9469-921f5dea8c52`。Vision → Evidence → Explanation → Critic 四次调用均完成，总观察耗时 16.843 秒，冻结证据版本 1、草稿版本 1，保存 6 条声明，覆盖全部六区段。Critic 返回 `NONE`，最终状态为 `REVIEW_READY`。

独立核验保存的上下文与结果，确认四角色绑定同一推理摘要，后续角色接收到 Vision 结果，Critic 收到实际冻结草稿和证据，六区段和逐条原文引用均符合要求。`REVIEW_READY` 表示可进入后续医生复核，不表示已经批准发布。

**受限场景：合成标签 `glaucoma`。** taskId 为 `abed3278-b030-42ff-bdb8-e9541d4d71e4`。前三个角色实际调用完成，耗时 16.115 秒；Explanation 将不相邻原文片段拼接为单条引用，违反连续原文引用要求。产品以 `INVALID_CITATION` 限制任务，没有保存草稿，也没有继续调用 Critic。这是一次真实生成失败，同时验证了引用校验能够阻止无效草稿继续流转。

本轮样本量仅 2 个，不能据此给出稳定成功率或临床有效性结论。真实 Critic 提出补证、重写的循环本轮未观察到，仍只有工程专项证据。

**四、排查过程与发现的问题**

| 问题 | 已确认事实 | 本轮处理与剩余影响 |
|---|---|---|
| 凭据读取错误 | 旧本地 profile 凭据的两轮运行共 4 次请求返回 401；最初只检查进程环境，漏掉 Windows 用户级变量 | 按用户提示读取用户级 `DASHSCOPE_API_KEY`；修正临时运行脚本，没有修改用户变量或产品配置 |
| 默认运行超时 | 使用正确用户级凭据后，未显式关闭 thinking 的两个场景均在 Vision 触发单次 20 秒时限 | 验收配置关闭 thinking 后完成后续验证；默认配置的可靠运行仍未验收 |
| 真实引用不合规 | 一个场景生成拼接引用，被 `INVALID_CITATION` 拒绝 | 保留失败证据；尚未优化产品输出策略，也未放宽引用要求 |
| 临时核验器误报 | Java 时间数值的 JSON 内存节点类型不同，导致成功场景的 Critic 上下文比较误报 | 用独立脚本重读同一批 JSON，逐字段确认一致；修正临时比较器，未重跑模型或更改产品状态 |

原始 `scenario-results.json` 保留核验器修正前的比较字段；成功场景上下文一致性的最终判断见 `independent-trace-check.json`，相关差异已在技术报告说明。
