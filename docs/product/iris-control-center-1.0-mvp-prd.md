## 1. 产品概述

### 1.1 背景

Iris 已具备 React 管理端、Spring Boot 后端、Spring AI Agent、Python gRPC 推理和多智能体协作等能力。

但当前存在三个问题：

1. 系统品牌及部分站点信息依赖静态资源或源码，修改需要重新构建或部署。
2. Spring YAML、环境变量以及各模型客户端中的配置来源分散，缺少统一的配置定义、管理和审计机制。
3. 缺少配置草稿、验证、发布、版本追踪与安全回滚机制。

因此，需要建设独立的系统配置中心。

### 1.2 MVP 目标

- G1：实现站点名称、Logo、Favicon 等品牌资源的后台配置。
- G2：建立类型明确、具备默认值与服务端校验的配置体系。
- G3：提供草稿、发布、版本历史和回滚能力。
- G4：支持 AI 服务商连接元数据管理、密钥引用与安全连接测试。
- G5：确保配置操作受到服务端权限控制，并形成完整审计记录。
- G6：为未来统一模型能力目录和模型路由层预留结构，但第一期不改变现有模型执行路径。

### 1.3 明确不做

MVP 不包含：

- 自由切换正在使用的生产 LLM 或 Embedding 模型。
- Python 真实推理启停、模型权重管理、GPU 调度。
- 多 Agent 工作流编辑、角色模型动态切换。
- RAG 索引重建或检索参数在线调整。
- 后台直接存储、回显或修改明文 API Key。
- 数据库、Redis、COS、CORS、Session 等基础设施配置的在线修改。
- 多租户、医院级品牌隔离、配置市场和低代码工作流编辑器。

上述能力不属于本次 MVP 的交付承诺。

## 2. 角色与权限

### 2.1 角色定义

**普通用户**

仅可读取公开发布的品牌配置。不能访问内部配置、凭据元数据、审计记录。

**系统管理员**

基于现有 `admin` 角色，具有查看配置、编辑草稿、上传品牌资源、执行受限连接测试的权限。

**配置发布者**

第一期不强制引入新的数据库用户角色。通过服务端独立权限策略，将发布与回滚权限授予经过授权的管理员。

不能仅依赖 React 的 AdminGate 判断权限。

### 2.2 权限动作

| 权限代码 | 能力 |
|---|---|
| CONFIG_READ | 查看管理配置 |
| CONFIG_EDIT | 创建、修改草稿 |
| CONFIG_VALIDATE | 校验草稿 |
| CONFIG_PUBLISH | 发布配置 |
| CONFIG_ROLLBACK | 回滚配置 |
| CONFIG_TEST_CONNECTION | 测试服务商连接 |
| CONFIG_AUDIT_READ | 查看审计记录 |

服务端对每个 API 独立鉴权。敏感写操作继续执行 CSRF/Origin 等既有安全检查。

## 3. 管理端信息架构

新增一级入口：

`系统管理 → 系统设置`

建议路由：

- `/admin/settings/general` — 品牌与站点
- `/admin/settings/providers` — AI 服务商
- `/admin/settings/versions` — 配置版本
- `/admin/settings/audit` — 操作记录

系统设置页面复用现有 `AdminLayout`、AdminNav、表单组件及双主题设计令牌。

页面采用：

- 左侧分类导航。
- 右侧配置表单。
- 顶部当前配置版本、是否有未发布修改等状态。
- 底部保存草稿、校验配置、预览差异与发布操作。

当存在未保存修改时，切换页面应提示用户，防止编辑内容丢失。

不重新设计管理端外壳，不调整 Iris 2.1 已冻结的全局视觉体系。

## 4. 功能需求

### FR-01 强类型配置定义与默认值

优先级：P0

建立 Config Registry，由后端代码显式注册允许管理的配置项。

每项至少包含：

- `key`：稳定唯一标识。
- `type`：STRING / ENUM / BOOLEAN / ASSET_REF / PROVIDER_REF 等。
- `defaultValue`：默认值。
- `required`：是否必填。
- `validation`：长度、枚举、格式及依赖规则。
- `sensitivity`：公开、管理员可见、敏感引用。
- `mutability`：动态生效、需要发布、部署控制。
- `schemaVersion`：配置契约版本。

本期仅注册已批准进入 MVP 的配置项，不自动导入全部 Spring Environment 属性。

初始化时，既有 Iris 默认品牌信息必须仍能正常工作。

未知配置项不得通过 API 写入。

### FR-02 配置草稿、发布、版本历史和回滚

优先级：P0

配置分为：

- DRAFT：正在编辑的草稿。
- VALIDATED：某个草稿修订已通过校验。
- PUBLISHED：发布成功的不可变版本。
- REJECTED / FAILED：校验或发布失败的操作结果。

修改已经校验的草稿后，原有校验结果必须失效。

发布流程：

1. 管理员保存草稿。
2. 后端校验配置。
3. 系统展示相对当前发布版本的差异。
4. 具备权限的管理员执行发布。
5. 数据库事务原子更新当前生效版本指针。
6. 新的配置读取使用新版本。
7. 生成不可变发布记录和审计记录。

配置发布必须使用乐观并发控制，防止旧编辑页面覆盖其他管理员已经发布的更新。

**回滚不是修改旧版本或删除历史。**

回滚操作基于目标历史快照生成一次新的发布记录，并保留回滚来源。

首期仅提供单实例的原子切换语义；跨实例一致性作为未来扩展要求，不虚称已经支持分布式一致发布。

### FR-03 管理员鉴权与操作审计

优先级：P0

必须审计：

- 配置草稿创建、修改。
- 配置校验失败及关键拒绝原因。
- 配置发布成功或失败。
- 配置回滚。
- 服务商连接创建及修改。
- 服务商连接测试。
- 未授权的敏感操作尝试。

审计字段至少包含：

`eventId`、`actorId`、`action`、`targetId`、`requestId`、`beforeVersion`、`afterVersion`、`result`、`reasonCode`、`occurredAt`。

审计记录不得包含真实 API Key、患者信息、完整模型请求或响应内容。

对于成功发布和回滚，审计记录与发布事务应具有一致的持久化保证；禁止出现配置已发布但没有对应成功审计记录的状态。

普通管理员不可修改或删除审计历史。

### FR-04 站点名称、Logo 与 Favicon

优先级：P0

配置项：

| Key | 类型 | 默认值 |
|---|---|---|
| `brand.siteName` | STRING | Iris |
| `brand.shortName` | STRING | Iris |
| `brand.logo.light` | ASSET_REF | 内置浅色品牌资源 |
| `brand.logo.dark` | ASSET_REF | 内置深色品牌资源 |
| `brand.favicon.light` | ASSET_REF | 内置 Favicon |
| `brand.favicon.dark` | ASSET_REF | 内置 Favicon |

名称长度建议为 2–40 个用户可见字符，具体字符计数规则由前后端契约统一规定。

Logo 首期接受 PNG、WebP。Favicon 接受 PNG、ICO。不得接受未经安全处理的 SVG、远程 URL 或可执行文件内容。

建议限制：

- Logo 最大 1 MiB。
- Favicon 最大 256 KiB。
- 图片尺寸与像素总量必须有上限。
- 服务端根据真实文件内容验证格式，不能只检查扩展名。

文件使用服务端生成的 Asset ID 引用。

上传成功不等于发布成功。未发布品牌资源不应出现在公开站点。

公共品牌读取接口只暴露允许公开的展示字段。

### FR-05 品牌资源双主题适配

优先级：P0

支持 Light / Dark 两套品牌资源。

适用位置：

- 用户端全局品牌标识。
- 管理端侧栏品牌标识。
- 登录与注册页面。
- 浏览器标题与 Favicon。
- 其他由 Phase 0 识别出的共享品牌展示位置。

品牌配置不得改变页面的医学风险色、全局安全语义或已有设计令牌。

主题切换时，应同步选择相应品牌资源，不产生明显错误主题资源的长期残留。

未配置某一主题资源时，应使用该主题对应的内置默认资源，而不是直接使用可能失去对比度的另一主题图片。

资源异常、配置加载失败时，使用内置 Iris 默认品牌。

### FR-06 服务商连接元数据及密钥引用

优先级：P0

服务商连接模型：

`connectionId`、`displayName`、`providerType`、`baseUrl`、`secretRef`、`enabledForTesting`、`revision`、`createdAt`、`updatedAt`。

首期适配已存在的 DashScope / OpenAI 兼容服务配置模式。

密钥引用由受控枚举或服务端注册表提供，例如：

`env:DASHSCOPE_API_KEY`

不允许浏览器提交任意环境变量名称，然后要求后端读取其内容。

服务端可以使用环境变量或已有受控密钥来源解析凭据。

响应中只返回脱敏状态，例如：

`CONFIGURED` / `MISSING` / `INVALID_REFERENCE`。

MVP 不将服务商连接配置直接接入所有生产模型调用。新增、修改或测试服务商连接不得隐式改变正在运行的 Agent 模型。

### FR-07 管理端配置界面

优先级：P0

提供：

- 当前发布配置与草稿区分。
- 表单校验及字段级错误提示。
- 品牌资源上传和双主题预览。
- 服务商连接列表和状态。
- 连接测试反馈。
- 发布差异预览。
- 配置版本历史和回滚确认。
- 审计查询。
- 加载态、空态、错误态和权限不足态。

必须支持桌面与移动端基本操作，键盘导航、焦点可见性和可读的错误提示。

不能只用颜色表达配置状态。

### FR-08 服务连接测试与配置校验

优先级：P0

分成两种不同能力。

**配置静态校验**

检查字段类型、必填项、长度、资产归属、允许的服务商类型、密钥引用、配置版本及字段依赖。

**连接能力测试**

由服务器端执行有限的、明确授权的连接请求，至少检查：

- 目标地址是否合法。
- 密钥引用能否解析。
- 服务商能否返回预期的鉴权或能力响应。
- 是否发生超时、鉴权失败、限流或服务异常。

连接测试不得发送真实患者数据。

自定义 Base URL 仅允许符合部署侧目标白名单的地址；必须防护 SSRF、DNS Rebinding、重定向绕过及内网元数据访问。

测试需要有固定超时、响应大小限制、并发上限和操作限流。

连接测试成功只能证明**当次测试在指定检查范围内成功**，不能表示模型一定满足所有 Agent 任务，也不能等同于生产可用性保证。

## 5. 数据与服务架构

### 5.1 推荐数据对象

- `ConfigDefinition`：由代码维护的强类型配置元数据。
- `ConfigDraft`：可编辑草稿，包含 revision。
- `ConfigRelease`：不可变发布快照，包含 schemaVersion、releaseVersion、digest。
- `ConfigActivePointer`：当前发布版本。
- `BrandAsset`：品牌资源、内容哈希、格式和存储引用。
- `ProviderConnection`：服务商连接元数据与凭据引用。
- `ConfigValidation`：校验结果、草稿修订号与校验时间。
- `ConfigAuditEvent`：不可随意修改的操作审计事实。

配置对象中不得持久化明文 API Key。

`ConfigRelease` 应包含所有已发布配置的版本化引用；历史版本不得因服务商连接元数据后续被修改而改变含义。

### 5.2 配置解析规则

运行期配置按以下原则处理：

1. 部署级安全边界不可被数据库覆盖。
2. 动态业务配置只从已发布、已校验的版本读取。
3. 缺省值由 Config Registry 提供。
4. 配置读取异常不能自动使用未发布草稿。
5. 未知 Schema 版本不能静默忽略关键字段。
6. 无法获得可信配置时必须按配置类别处理：品牌可降级内置默认值，敏感运行能力必须失败关闭。

### 5.3 API 契约建议

以下是建议路径，正式路径需在 Phase 0 结合现有 Controller 风格确定。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/system/brand` | 公开品牌配置 |
| GET | `/api/admin/control-center/registry` | 强类型配置定义 |
| GET | `/api/admin/control-center/active` | 当前发布版本 |
| POST | `/api/admin/control-center/drafts` | 创建草稿 |
| PUT | `/api/admin/control-center/drafts/{id}` | 更新草稿 |
| POST | `/api/admin/control-center/drafts/{id}/validate` | 校验草稿 |
| POST | `/api/admin/control-center/drafts/{id}/publish` | 发布配置 |
| GET | `/api/admin/control-center/releases` | 版本列表 |
| POST | `/api/admin/control-center/releases/{id}/rollback` | 生成回滚发布 |
| POST | `/api/admin/control-center/providers/{id}/test` | 连接测试 |
| GET | `/api/admin/control-center/audits` | 审计查询 |

接口成功响应沿用项目既有 `BaseResponse` 契约。

写操作应支持幂等或有效的并发冲突检测，避免重试产生重复发布。

## 6. Phase 0：强制源代码审计

### CFG-AUDIT-01 配置来源与消费点审计

必须扫描 Java、Python 算法服务、React、配置模板和 CI 环境。

重点查找：

- `@Value`
- `@ConfigurationProperties`
- `System.getenv` / `System.getProperty`
- `spring.ai.*`
- `eye-diagnosis.*`
- `agent.*`
- `mcp.*`
- `diagnosis.grpc.*`
- `import.meta.env`
- `.env*`、YAML 与部署文件
- Java/Python 默认参数和源码硬编码

产出《配置项清单》，每一项至少有：

| 字段 | 含义 |
|---|---|
| configKey | 配置名 |
| sourceFile | 配置来源 |
| consumer | 实际读取它的类或函数 |
| purpose | 业务用途 |
| classification | DEPLOY_ONLY / DYNAMIC / STATIC_POLICY / SECRET_REF |
| lifecycle | 启动绑定 / Bean 初始化 / 请求时读取 |
| risk | 变更风险 |
| migrationDecision | 保留 / 纳入 MVP / 后续重构 |

**准入条件：**

- 所有发现的配置来源与消费点均分类。
- MVP 配置不存在无法解释的多重事实来源。
- 安全与基础设施配置没有被错误归入动态配置。
- 需要重启才能生效的配置被明确标记。
- 每一项纳入动态管理的配置均有明确默认值与迁移规则。

### CFG-AUDIT-02 模型调用与配置来源审计

必须识别全部实际模型调用入口，包括：

- Spring 自动配置注入的 ChatModel。
- 手工创建的 OpenAiApi、ChatClient 或其他模型客户端。
- 多 Agent 的各角色模型构造或复用位置。
- Embedding、Rerank、视觉语言模型调用。
- Python 影像模型调用。
- 仅有名称但尚未调用模型的占位实现。

产出《AI 模型调用清单》：

| 字段 | 含义 |
|---|---|
| callSite | 源码位置 |
| taskType | Chat / Vision / Agent / Embedding / Rerank 等 |
| providerSource | Provider 来源 |
| modelSource | Model ID 来源 |
| credentialSource | 密钥来源 |
| lifecycle | 客户端构造和缓存时机 |
| runtimeBinding | 是否可动态解析 |
| migrationPlan | 保留 / 未来接入 Model Router |
| medicalRisk | 是否涉及患者影像、医学文本或受控结果 |

重点识别现有多 Agent 分支中真实调用路径，而不只是类名。

**准入条件：**

- 所有真实模型调用点均已登记。
- 识别直接构造模型客户端与自动注入模型的差异。
- 明确第一期不会引入假动态切换。
- 规划未来统一 `ModelRegistry` / `ModelResolver` 的接入点。
- 不破坏原有结构化输出、医学证据校验与授权边界。
- 确认所有服务商配置的真实凭据来源，不通过日志或文档泄露密钥。

审计必须基于实施前固定的 Git commit SHA，并同时说明 `ui` 与多 Agent 集成分支的适用范围。

## 7. 验收标准

### AC-01 强类型配置

- **AC-01-01**：启动一个全新实例，无数据库自定义配置时，可得到完整合法的 Iris 默认品牌配置。
- **AC-01-02**：提交未知 key，服务端拒绝写入，不产生有效配置。
- **AC-01-03**：提交错误字段类型、非法枚举、超长名称，返回具体字段错误。
- **AC-01-04**：部署保护字段不能通过配置管理 API 修改。
- **AC-01-05**：不兼容的配置 Schema 被识别并拒绝，不静默加载。

### AC-02 草稿、发布与回滚

- **AC-02-01**：保存草稿后，公开站点仍展示当前已发布版本。
- **AC-02-02**：修改通过校验的草稿，使其回到需要重新校验的状态。
- **AC-02-03**：发布成功后，公开配置返回新版本和对应内容。
- **AC-02-04**：模拟两个管理员并发编辑，过期 revision 不得覆盖新版本，返回明确冲突。
- **AC-02-05**：同一发布请求重复提交，不产生重复有效版本。
- **AC-02-06**：回滚产生新的发布版本，原历史记录不变。
- **AC-02-07**：模拟数据库发布事务失败，当前有效版本保持不变。
- **AC-02-08**：发布和回滚均存在完整审计记录。

### AC-03 管理权限及审计

- **AC-03-01**：匿名用户或普通用户无法读取管理配置。
- **AC-03-02**：普通 `admin` 若未被授予发布权限，无法调用发布与回滚端点。
- **AC-03-03**：直接调用后端 API 不能绕过前端权限限制。
- **AC-03-04**：所有敏感操作记录操作者、时间、目标、结果和关联版本。
- **AC-03-05**：审计、异常与 HTTP 响应均不包含明文 API Key。
- **AC-03-06**：CSRF 或 Origin 校验失败时，不产生有效配置修改。

### AC-04 站点名称及品牌资源

- **AC-04-01**：发布新站点名称后，约定范围内的导航品牌、页面标题等展示同步更新。
- **AC-04-02**：未发布的 Logo 不会出现在公开网站。
- **AC-04-03**：上传非图片文件、伪装扩展名文件或超限图片被拒绝。
- **AC-04-04**：客户端不能通过图片上传任意覆盖已有品牌资源。
- **AC-04-05**：配置读取或品牌资源加载失败时，回退内置 Iris 品牌资源。
- **AC-04-06**：旧版本资源在仍被历史配置引用时不会被错误删除。

### AC-05 双主题资源

- **AC-05-01**：Light 模式使用对应浅色主题品牌资源。
- **AC-05-02**：Dark 模式使用对应深色主题品牌资源。
- **AC-05-03**：切换主题后，Logo 和 Favicon 按约定更新。
- **AC-05-04**：缺失某一主题资源时使用明确的内置回退资源。
- **AC-05-05**：桌面、移动端及现有管理端结构保持可用，品牌配置不会覆盖设计令牌。

### AC-06 服务商连接元数据与密钥引用

- **AC-06-01**：管理员可新增和编辑受支持服务商的连接元数据。
- **AC-06-02**：服务端拒绝未注册的密钥引用。
- **AC-06-03**：管理端只能读取凭据状态，不能读取密钥内容。
- **AC-06-04**：没有有效凭据时展示 `MISSING` 或对应错误，而不是成功。
- **AC-06-05**：新增、编辑连接不会改变生产 ChatModel、Agent 或 Embedding 执行路径。
- **AC-06-06**：历史发布快照引用的连接修订信息可以追溯。

### AC-07 管理端交互

- **AC-07-01**：系统设置入口仅在授权管理区域展示。
- **AC-07-02**：草稿与已发布状态有清晰且非仅靠颜色的区分。
- **AC-07-03**：未保存编辑离开页面时有提示。
- **AC-07-04**：错误校验聚焦到相应字段并说明原因。
- **AC-07-05**：发布前可查看差异摘要与确认信息。
- **AC-07-06**：浅色、深色、桌面和移动布局无阻断性问题。
- **AC-07-07**：不得因增加设置中心而使已冻结的其他管理页面产生功能或视觉回归。

### AC-08 连接测试与校验

- **AC-08-01**：合法凭据及允许的服务商端点返回可解释的测试结果。
- **AC-08-02**：无效凭据、超时、限流、协议异常分别返回明确错误类别。
- **AC-08-03**：连接测试不包含真实患者信息。
- **AC-08-04**：禁止访问未授权内网、环回地址、云元数据端点或重定向后的受限目标。
- **AC-08-05**：测试操作受到超时、并发和频率限制。
- **AC-08-06**：测试失败不会修改当前生产配置。
- **AC-08-07**：涉及本次变更且将启用的服务商连接必须通过相应校验；未修改的既有连接不应无故阻塞纯品牌变更。
- **AC-08-08**：校验与测试使用的草稿 revision 与最终发布的 revision 一致，过期结果不可用于发布。

## 8. 非功能验收门槛

### 安全

- 无明文密钥泄露。
- 无未授权配置操作。
- 无部署级安全保护被绕过。
- 无任意 URL 探测与 SSRF 漏洞。
- 无利用上传文件执行脚本或覆盖任意对象的路径。

### 数据一致性

- 发布版本不可变。
- 活跃版本切换原子化。
- 回滚历史完整。
- 并发编辑不丢失更新。
- 审计与关键变更具备一致性保证。

### 性能与稳定性

- 公开品牌配置读取不应成为首页的阻断依赖。
- 配置管理 API 和连接测试使用独立超时与限流规则。
- 连接测试不能占满普通 Agent 请求的执行资源。
- 后端配置存储异常时，公开品牌有默认回退机制。
- 不要求动态配置重建全部 Spring Bean。
- 既有功能测试、编译检查与 CI 必须保持通过。

### 可维护性

- 配置定义只有一个可信注册源。
- 重要配置项具有明确所有者和消费位置。
- API、数据模型和版本化契约有自动化测试。
- Flyway 只增加新迁移，不修改已执行的历史迁移。
- 不引入额外配置中间件或重复实现现有安全基础设施。

## 10. 版本发布与验收结论

MVP 的完整验收结论应包含四种状态：

- **PASS**：全部必选验收标准通过，证据充分。
- **PASS_WITH_MINOR**：没有 P0/P1 问题，剩余问题不阻断既定交付目标。
- **BLOCKED**：存在尚未满足的前置条件，不能发布。
- **FAIL**：存在已验证的功能、安全或一致性缺陷。

实现完成不等于可以部署。正式上线仍需独立批准。

本 PRD 的首期成功标准是：

**管理员能够安全地管理 Iris 品牌和 AI 服务商连接元数据，配置变更具备校验、发布、追溯与回滚能力，现有 Agent、Python 推理和医学安全流程保持不变。**
