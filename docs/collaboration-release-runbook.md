# TASK-07：协作权限、监控与回退

本手册适用于 Java 线 V20 + React `web/` 的候选。默认关闭；工程验收不授权生产启用。执行与复核是两个状态机：`SUCCEEDED/PENDING` 仅表示辅助草稿已就绪，不能发布医学正文。批准后的每次读取和首次保存仍复验输入、来源、引用及冻结版本。V20补齐空会话依赖，不解决其他分支的迁移历史分歧；当前验收见[产品报告](testing/2026-11-12-realtime-product-acceptance.md)。

## 权限矩阵

| 操作 | 任务患者（含本人也是医生/管理员） | 其他患者 | 已分配医生 | 未分配医生 | 管理员 |
| --- | --- | --- | --- | --- | --- |
| 创建本人影像协作 | 本人任务及有效会话 | 不能代建 | 仅本人任务 | 仅本人任务 | 仅本人任务 |
| 快照 / SSE | 安全状态和患者事实 | 拒绝 | 分配绑定的协作元数据 | 拒绝 | 协作元数据；本人仍为患者投影 |
| 取消 | 允许 | 拒绝 | 拒绝 | 拒绝 | 允许 |
| 分配复核 | 拒绝 | 拒绝 | 拒绝 | 拒绝 | 允许，不能给患者本人分配 |
| 完整冻结材料 / 决定 | 拒绝 | 拒绝 | 允许 | 拒绝 | 拒绝 |
| 绑定版本原图 | 本人任务 | 拒绝 | 明确分配的任务 | 拒绝 | 只有本人任务 |
| 批准后的解释 / 引用 | 本人且本次发布门禁通过 | 拒绝 | 不能代读 | 不能代读 | 不能代读 |
| 拟保存内容 / 授权保存 / 回执 | 本人显式授权 | 拒绝 | 不能代签 | 不能代签 | 不能代签 |
| `GET /api/agent/collaboration-runs/operations` | 普通患者/医生拒绝；管理员身份可读聚合 | 拒绝 | 拒绝 | 拒绝 | 聚合状态与开关 |

管理员对协作元数据的许可不延伸到完整复核材料。当前 v1 事件不含原图地址、引用正文、claim 正文、模型原始响应、隐藏推理或医生意见。详细材料仍走医生复核接口。医生分配发生在草稿就绪后，当前不支持给运行中任务预分配医生。

每次读取以及 SSE 每批/每帧发送重新验证服务端会话和数据库角色/分配。患者投影优先于账号角色；本人是管理员也不能借协作接口读自己的未审草稿。过滤后的序号跳号合法。退出、角色变更、删除账号、分配撤回或对应展示开关关闭后停止详情发送。已送达的网络字节不可撤回，前端在收到拒绝后清除协作材料与影像 Blob。

## 开关

| 配置 | 默认 | 生效范围 |
| --- | --- | --- |
| `eye-diagnosis.collaboration.enabled` | false | 控制器、事件组件与 worker 总开关；排空后才关闭 |
| `eye-diagnosis.collaboration.admission-enabled` | false | 只拒绝新 run，503 `ADMISSION_DISABLED`；原幂等键可以回放 |
| `eye-diagnosis.collaboration.graph-enabled` | false | 仅新 run 的执行器；已有 run 保持 runtimeKind/workflowVersion |
| `eye-diagnosis.collaboration.patient-progress-enabled` | false | 患者投影及新受理；关闭后查询/SSE 为403，不影响后台及显式取消 |
| `eye-diagnosis.collaboration.clinician-detail-enabled` | false | 医生/管理员元数据查询和 SSE；不改变医生复核/患者发布的既有权限 |
| React `VITE_COLLABORATION_ENABLED` | 未设置即关闭 | 构建时决定协作入口；不构成后端鉴权 |

总开关打开还必须注入持久的256-bit `eye-diagnosis.collaboration.cursor-key`。多实例/重启共用同一密钥；不得使用测试夹具密钥。运行时、展示和新受理开关不授权模型绕过输入、证据或预算门禁。只打开后端总开关时，其余开关仍关闭。

**当前没有生产动态配置刷新或在线改开关接口。** Spring 配置在实例启动时注入；变更通过受控发布/滚动重启生效。测试夹具的 `/api/test/flags` 仅存在于 test classpath，不能部署。各实例切换期间仍在旧配置下服务的实例可能继续受理/发送；需要立即全局停止时，先在现有流量入口阻断新 POST/受影响读路径，再按变更流程更新全部实例。流量入口操作本卡没有实施或验证。

## 监控

管理员带服务端登录会话请求 `GET /api/agent/collaboration-runs/operations`，响应 `Cache-Control: no-store`。只返回本实例开关、本地队列深度，以及全库按 runtimeKind/status/stopReason 聚合的 runCount；不返回患者/医生标识、runId、taskId、正文、对象地址或游标。该读接口不派发任务、不调用模型、不产生新事件。

回退排空按全库 `ACCEPTED/RUNNING/CANCEL_REQUESTED` 计数，不能只看本地队列为0。监控采样跨语句，不是原子“可安全回退”证明；排空后仍要逐实例确认 worker 停止派发、没有在途调用及兼容版本安排。

建议由现有监控系统采集状态/受限原因、队列、503/429、模型失败和租约到期日志；告警内容仅含分类与计数。外部采集器、通知渠道、生产阈值和责任人尚未配置，禁止将本接口写成已完成生产告警。`FAILED/PROVIDER_AUTH` 等应按错误分类处理，不能通过放宽医学门禁消除告警。

当前工程防护参数：每患者最多2个活动 run；worker 队列16；模型每run最多8次、总90秒、单次20秒；Graph租约10秒、每秒续租；事件轮询250ms、每批32；每进程8条/每患者2条订阅；缓冲64帧、心跳15秒、连接180秒；游标7天。订阅通过鉴权后的首批会立即发心跳以刷新响应，后续按15秒节奏。参数来自实现，尚无生产容量/SLO验证。没有事件清理任务，不要在保留期内外部删除后继续承诺游标补偿。

## 回退步骤

**V28 之后的二进制回退限制**：数据库应用 V28 后，直接换回不含该脚本的旧产物
（例如 `7c028b80`）会因 `validate-on-migrate=true` 报 missing applied migration，
即使工具审计默认关闭、残留审计表不参与聊天也不能绕过启动校验。回退候选必须保留
已应用迁移及校验和并单独验证兼容性，或走经批准的数据库快照恢复流程；不得通过
`repair`、`ignoreMigrationPatterns`、关闭校验或删除 history 强行启动。
迁移真源与目标库识别见[迁移矩阵](architecture/migration-matrix.md)。本轮仅记录限制，
未执行旧二进制回退或数据库恢复演练。

1. 记录候选完整SHA与内容清单、当前配置、各实例版本、数据库迁移history/校验和、聚合活动计数。检查数据备份和兼容worker，不能修改/删掉已应用的V18/V19。
2. 停止新受理：部署 `admission-enabled=false`，保持总开关及兼容worker。旧幂等请求只回放；新的合法请求503且不创建run。需改变后续执行器时设 `graph-enabled=false`，只影响新run。
3. 只撤回展示时关闭相应投影开关；活动SSE被后续授权检查关闭。前端入口可恢复为普通问答，后台运行保持执行器归属；关闭页面/连接不是任务取消。
4. 让活动run由原兼容worker完成，或由owner/admin显式调用持久取消接口。患者投影和医生详情关闭时仍允许owner/admin取消。医生、其他患者不能借回退操作取消。
5. 反复核对全库活动计数与实例在途情况。已有Graph run不能交给旧Coordinator从头跑；保留token/checkpoint/预算/事件及复核记录。取消不保证提供方停止计费。
6. 完成排空、确认没有在途/待恢复工作后才关闭总开关或回退二进制。新表保留；旧版本必须已证明能安全忽略新schema。当前卡未运行真实旧二进制回退，未证明生产环境兼容，故此步是待验证操作。
7. 恢复候选时用原密钥及数据库继续授权快照/重放，禁止重建task/run模拟恢复。来源、审核和保存许可每次独立复验。验证普通问答兼容及跨账号拒绝后再考虑新受理。

本卡的已运行演练是进程内配置切换 + 浏览器真实HTTP/MySQL + Graph跨JVM恢复专项，使用合成模型/推理/存储。生产动态配置、真实入口阻断、多实例滚动发布、真实旧二进制及SLO仍未演练。医学材料/OOD与TASK-06扩大评估不因该工程验收升级。
