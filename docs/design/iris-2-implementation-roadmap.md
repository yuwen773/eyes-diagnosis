# Iris 2.0 · 前端实施路线图

> **配套**：`../../DESIGN.md`（新规范）、`iris-2-rule-change-matrix.md`（规则变更对照表）、
> `IRIS_2_DESIGN_REFERENCE_BRIEF.md`（设计简报）。
>
> **原则**（来自简报 §4 与本次任务约束）：
>
> - **不一次性全面翻新**。基线顺序是：PR #52 工程验收 → 规范文档合并 → 首页二期 →
>   管理端 F+G → Agent/影像 H+I。
> - **本轮及后续每轮都不改后端 API 契约**（Architecture Frozen）。视觉升级只换皮、
>   换结构；后端要改的（如多 Agent 事件协议）单独走契约评审，不夹在设计 PR 里。
> - **每阶段独立分支、独立 PR、独立验收**。不堆叠长命分支。
> - **每阶段必须给真实浏览器截图**：390 / 768 / 1440 / 1920 × Light/Dark，
> 加上该阶段特有的降级路径。
> - 阶段之间**不合并**，除非本阶段的验收门禁全绿。

## R0 · PR #52 工程验收与合并

**状态**：🅿 PR #52（`feat/iris-2-optic-flow` → `ui`）已开，**未合并**。

**为什么它是 R1 的前置**

**已完成**

  实时订阅、上下文丢失切静态。

- 第三方声明：固定上游 commit SHA + 许可原文 + 逐字比对记录。

**验收门禁**
`typecheck` / `lint` / `test`（36 文件 253 例）/ `build` 全绿；
真实 `npm run dev` 下 StrictMode 验证；390/768/1440/1920 × 亮暗截图。

**未执行项（如实记录，不掩盖）**
`npm run test:e2e` 未跑（无后端会话环境与 `E2E_USER` / `E2E_PASSWORD`）；
帧率 / GPU 占用未实测（软件渲染下数字无意义）。

**遗留债**（写进 §8，不阻塞合并）
首屏光带参数是手调的；品牌层只覆盖首屏（→ R2）。

## R2 · 首页二期 · 品牌层收敛

**目标**
首页从"首屏是 Iris 2.0、下面还是旧骨白"变成**整页是一套品牌面**。

**前置**
R0、R1 已合（`--brand-*` 令牌由 R0 带进 `tokens.css`）。
令牌与容器要分开看：**`--brand-*` 是跨场景令牌，`.iris2` 只是品牌视觉容器类**
（只在首页首屏），合并后两者都可用，但不要在管理端/Agent 页套 `.iris2`。

**范围**
1. **品牌导航**：字标 + 药丸导航 + 主 CTA「探索平台」，字标用现有金属虹膜标
   （`web/public/iris-mark-metallic-light.svg` / `-dark.svg`）。
2. **首页下半部分统一到 `--brand-*`**：消除"首屏银蓝 / 下半页骨白"同页共存
   （§8 的技术债之一）。下半页已有的真实医学内容（影像示意 / 样本 / 流程 /
   判读记录 / Agent / 边界声明 / 行动）**内容不动，只换语境**。
3. **免责与概念预览口径**：首屏已有的「AI 辅助信息展示 · 不构成临床诊断结论」
   与「流程示意 · 非实时结果」沿用；下半页新增的概念性区块同样要标
   「CONCEPT PREVIEW · 非实时结果」，**未上线的功能写"规划中"**。

> 首屏的玻璃流程卡、三张入口卡、仪器读数条、双 CTA 与标题排版**已在 PR #52 中落地**
> （**尚未进入 `ui`**，R0 合并后才可用），本阶段**不重做**它们——除非有具体理由，并单独记录理由。

**不做**
- 不换首屏光学渲染器（PR #52 的实现是基线，**禁止无理由推翻已有布局**）。
- 不加第二个 GPU 背景、不加粒子、不加滚动视差。
- 不放患者影像、不放虚构准确率。
- 不改后端。

**验收**
- 4 档宽度 × 亮暗 × 首页全页截图；`prefers-reduced-motion` 与静态降级各一张。
- 品牌层对比度断言（`tokens.contrast.test.ts`）保持绿。
- 键盘走查：导航与所有 CTA 可达、焦点可见。
- 包体不显著增长（首屏已是 +80.9 kB 字体；导航与卡片应基本为 CSS 成本）。

**风险**
首页两种底色共存是**当前已知状态**，改它会牵动 `index.css` / `app.css` 的语境类，
可能出现浅色/暗色对比回退。**每个区块单独迁移、单独截图**，不整页换。

## R3 · 管理端 F+G · 成熟 SaaS 视觉

**目标**
管理台从"旧 B 档（0 圆角、墨色主按钮）"升级到 `DESIGN.md` §2.2 的目标外观。

**前置**
R1 已合。**不依赖 R2**（管理端与首页不共享语境类）。

**范围**
1. **新增 `.is-admin` 语境类**（第 2 层场景语境）：管理面底色、面板材质、
   品牌色主操作的取值来源。组件只消费上下文别名，不改组件逻辑。
2. **形状与层次**：卡片圆角 8–12px、实体卡片 + 极淡墨色阴影、发丝描边；
   去除多重内嵌容器；沿用现有 `--shadow-overlay` / `--shadow-modal`。
3. **主操作色**：钴蓝 `--brand-primary`（当前是墨色/信号橙）；
   信号橙退回"当前态/重点"本职。
4. **暗色主题**：深海蓝背景与分层面板；图表系列亮度单独调整；
   **不把所有 KPI 渲染成发光渐变**。
5. **图表口径与第二通道**：`--viz-series-*` 上线；每个系列配读数表 / 条端直标 /
   图例 / 线型之一；tooltip 与 `aria-label` 带系列名；
   **全量 / 时间窗口 / 分页**三种口径写在标签上。
6. **表格**：`DataTable` 的表头 `aria-sort`、排序只在后端支持时出现、
   分页口径文案（"本页 N / 全量 M"）。
7. **弹层**：Modal / Drawer 已是 Base UI；本阶段只做**视觉变体**（圆角 8px、
   墨色半透明遮罩而非纯黑、面板表面层次）。

**不做**
- 不自研排序 / 焦点陷阱 / Dialog / 图表——TanStack Query / TanStack Table /
  Recharts / Base UI 已就位（简报 §2.2 明确要求）。
- 不把首页 Beams 铺到管理页面。
- 不虚构 KPI（概念稿里的营收、准确率一律不进）。
- 不改后端端点。

**验收**
- 7 个管理页 × 4 档宽度 × 亮暗截图。
- **切时间窗立即失效 + 占位**的回归用例保持绿（`AdminDashboardPage.test.tsx`）。
- 图表的第二通道与口径标注逐图核对。
- 对比度：正文 ≥4.5:1、图形 ≥3:1，亮暗两套都实测。

**风险**
管理端页面多、状态多（加载/空/错/无权限），改语境类容易让某些状态回落到根级
令牌。**逐页截图，不批量替换类名。**

## R4 · Intelligence H+I · 协作台与影像工作台

**目标**
从"一个聊天框"变成"看得到协作的工作台"。

> ⚠️ **本阶段协议先行，界面在后。**
> 后端当前只有 `assistant / reasoning / tool-request / tool-response / confirm`
> 与终态 `event: "done"`。多 Agent 编排、任务依赖、运行态推流**都不存在**。
> **在协议定下来之前，界面上一行都不许画假状态。**

**前置**
R1 已合；**且**后端事件契约评审通过（单独 PR，不在本路线图里夹带）。

**阶段拆成三小步，各自独立 PR**

| 小步 | 内容 | 前置 |
|---|---|---|
| R4.1 | **事件契约**：定义 `runId, agentId, stepId, status, tool, evidenceRef, timestamp`；后端产出真实事件；前端只做**日志式**事件流（不做节点图） | 后端契约评审 |
| R4.2 | **协作视图**：Agent 节点与状态、工具调用、时序、任务依赖；运行态动效绑定真实事件 | R4.1 |
| R4.3 | **影像工作台**：主画布（中性深色，任何主题）、双眼对比、缩放平移、标注/疑点、影像质量提示；证据区结构化 | R4.2 + 影像数据通道 |

**范围要点**
- **影像画布中性深色**：任何主题下都用稳定中性灰阶，不染品牌蓝、不发暖光。
- **四套语义分离**：运行态（品牌蓝/冰青）、智能体类别（局部紫）、
  待人工复核（独立审查状态）、临床严重度（`--risk-*`）。**"高风险"绝不能用紫色渐变。**
- **对话区是子区域**，不是全屏唯一内容。
- 证据区必须有：模型版本、工具来源、影像来源、引用证据、置信度与限制、
  复核与来源标注、免责。

**不做**
- 不复制心脏扫描 / 生命体征 / 急诊队列等非眼科语义。
- 不引入基因合成、3D 生物模型等非本产品领域概念。
- 不为沉浸感盖住影像或降低可读性。
- 不自研 SSE 客户端、不另造编排引擎。

**验收**
- R4.1：SSE 事件有**录制回放**测试；前端事件流与真实事件一一对应。
- R4.2：状态语义四色不混用（对照度 + 视觉走查）；reduced-motion 下运行态降级为静态标记。
- R4.3：影像画布在 Light/Dark 下都做中性灰阶校验；标注与病灶对比度实测。

## 明确不在路线图里的事

- 后端 API 契约变更（多 Agent 事件协议走**独立的契约评审**）。
- 多 Agent 任务编排引擎、证据存储与检索后端。
- 影像标注的算法实现（模型侧另立项）。
- Vue 线 `frontend/` 的任何工作（已弃用）。
- 为了"看起来像"而引入新的 UI 库、动画库、图表库或特效库。
