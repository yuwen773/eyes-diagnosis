## R2 · 首页二期 · Brand Experience R2

**目标**
首页从"首屏是 Iris 2.0、下面还是旧骨白"变成**整页是一套品牌面**：
有真实可辨的玻璃材质、悬浮胶囊导航、完整品牌页脚，三者共享同一套光学语言。

**前置**
R0、R1 已合（`--brand-*` 令牌由 R0 带进 `tokens.css`）。
令牌与容器要分开看：**`--brand-*` 是跨场景令牌，`.iris2` 只是品牌视觉容器类**
（只在首页首屏），合并后两者都可用，但不要在管理端/Agent 页套 `.iris2`。

**为什么拆成五个小步**
R2 的工作量横跨材质、渲染器、导航、页脚与整页版式，一次性做完会得到一个
无法审查的巨型 diff。**五步各自独立 PR、各自独立验收**：

| 小步 | 名称 | 核心结果 | 依赖 |
|---|---|---|---|
| **R2-00** | Glass Material Foundation | 可复用的品牌玻璃材质体系（5 种材质各有令牌与变体） | R2-01 ~ R2-04 |
| **R2-01** | Optic Glass Fidelity | 光学主视觉从"蓝色发光流体"升级为可辨识的**透明光学玻璃带** | R2-00 |
| **R2-02** | Floating Brand Header | Livera-inspired 悬浮胶囊导航（Brand 变体，不污染共享导航） | R2-00 |
| **R2-03** | Brand Footer | 深海蓝实体品牌页脚（信息架构 + 可信信息分层） | R2-00 |
| **R2-04** | Full-page Brand Unification | 首页从 Header 到 Footer 统一，消除上下半页材质断层 | R2-01 ~ R2-03 |

### R2-00 · Glass Material Foundation

**范围**
1. 在 `tokens.css` 与 `brand.css` 上扩展**五种品牌材质**，各有令牌、双主题取值与
   不支持 `backdrop-filter` 时的静态替代：

   | 材质 | 用途 | 视觉特征 |
   |---|---|---|
   | Optical Glass | 首页连续光学带 | 带体厚度、边缘反射、透光层次、银蓝高光 |
   | Frosted Glass | 悬浮导航 | 轻磨砂、稳定可读、柔和镜面边缘 |
   | Layered Glass | Hero 信息卡 | 半透明、内侧高光、背景透光与空间层次 |
   | Soft Glass | 首页入口卡 | 清爽、细描边、有限模糊 |
   | Solid Brand Surface | 页脚与承载大量文字的区域 | 实体深蓝表面，强调可读性 |

2. 规范每种材质的：背景透明度、表面渐变、边缘描边、镜面高光、空间投影、
   `backdrop-filter` 强度、Light/Dark 对应关系、文本对比度与焦点状态。
3. 材质变量**可复用、不重复定义**；必要值走语义变量，不散落硬编码 RGBA。

**不做**
- 不新增重型 UI 库或动效依赖；不引入第二个 GPU 渲染器。
- **禁止**"高度不透明的普通卡片 + `blur(30px)`"冒充高级玻璃——
  玻璃必须有可辨认的背景透光层次。

**验收**
- Light / Dark 材质示例完整；玻璃边界与透光层次清楚。
- 正文对比度 ≥4.5:1；不支持 `backdrop-filter` 时仍然美观。
- 材质令牌可复用，无重复定义；无新增重型依赖。

### R2-01 · Optic Glass Fidelity

**目标**
把首屏主视觉从"蓝色发光流体"升级为**可辨识的透明光学玻璃带**：
连续流动的整体形态 + 透明带体 + 厚度感边缘 + 冷银镜面高光 +
钴蓝与冰青之间的层次反射 + 内部细密光学纤维 + 前后空间关系。

**范围**
1. 优化现有 vendored Beams 的**着色器参数、合成参数与材质配色**，
   局部改进优先，**不重写渲染器**。
2. 修 Light 模式的纤维可见性问题：现有 `mix-blend-mode: multiply` 配偏白 stroke
   会让细纤维在亮色环境里几乎不可见——按主题分别处理混合方式与 stroke 取值。
3. Light 与 Dark **各自一套材质表现**（冰川银蓝 / 午夜蓝），**不得**简单反色。
4. Hero 的玻璃流程卡与三张入口卡同步精修：透光关系、边缘高光、内阴影层次、
   玻璃与文字可读性的平衡。**亮色玻璃不显脏灰，暗色玻璃不成为不透明深蓝板**。

**不做**
- 不新增第二个 WebGL 实例；细纤维仍是低成本 SVG 合成层。
- 不引入 Three.js 或额外 GPU 后处理框架。
- 不把大量透明模糊层盖在主要内容上。
- 若修改 vendored shader，**必须**在 `THIRD-PARTY-NOTICES.md` 记录相对上游的
  差异，不再宣称"与上游逐字一致"；保留许可原文与固定上游 commit。

**验收**
- 优化前后**同宽度、同主题、同页面状态**的对比截图（不能只给 CSS diff）。
- 1440px Light/Dark 的 Hero 全图、光带材质放大图、玻璃信息卡放大图。
- 390px 移动端效果、动态运行与暂停后的画面、WebGL 降级截图。
- 性能与资源体积变化有记录。

### R2-02 · Floating Brand Header

**目标**
首页顶栏升级为 **Livera-inspired 的悬浮胶囊导航**（借鉴结构，不复制资产），
同时保持 Iris 自己的品牌身份。

**范围**
1. 桌面端结构：**左侧 Brand（金属虹膜标 + Manrope 字标）/ 中央胶囊导航 / 右侧功能操作**
   （主题切换、现有 `AccountMenu`、登录或用户入口、必要的主 CTA「开始判读」）。
2. 胶囊容器：轻磨砂玻璃表面 + 细微边缘高光 + 有辨识度但不夸张的空间阴影；
   当前路由有**独立的高亮胶囊**；Hover / Focus / Active 状态区分清楚；
   路由切换过渡流畅克制，**不引入布局抖动**。
3. 导航目的地只用真实可用路由：`/`、`/diagnosis`、`/agent`、`/news`。
4. 玻璃行为：页面顶部更轻更透明；滚动后适当提升玻璃底色强度；
   **与 `useHeadInvert()` 的反相机制协同**——
   不让旧的 `style.background` 覆盖新玻璃材质、不因反相变成实体矩形、不产生跳变或闪烁。
5. 移动端：Logo 保持可辨认、主题切换仍可用、导航收为菜单按钮；
   **复用现有 `MobileNav`** 的路由与认证逻辑；焦点正确进入、Escape 关闭、
   关闭时焦点返回触发按钮、滚动锁正确、触控目标 ≥44×44px、无横向溢出。
   **不把桌面胶囊缩小后塞进 390px**。

**边界（硬约束）**
`SiteHeader` 是**共享组件**。首页用新的悬浮胶囊 Header，
**不代表 Clinical / Management / Intelligence 也套营销风格的玻璃导航**。
必须走明确的 **Brand 变体**或等价的受控场景化实现，
**不得**通过改 `.site-head` 全局选择器让所有页面被动获得玻璃材质。

**验收**
顶部初始态 / 中途滚动态 / 深色区段反相态 / 当前路由高亮态 /
登录与未登录 / Light / Dark / 390px 移动菜单展开与关闭 / 键盘 Tab 与 Escape /
锚点与 Sticky 偏移 / Console 无新增错误——逐项真机验证并截图。

### R2-03 · Brand Footer

**目标**
把"仪器铭牌式 Footer"升级为能承接完整 Iris 2.0 品牌体验的官网页脚，
采用 **Deep Ocean Blue · Solid Brand Surface**（深海蓝实体品牌背景，不强制玻璃模糊）。

**范围**
1. **三层信息架构**：品牌收尾（虹膜标 + 字标 + 品牌主张）→ 信息导航
   （产品 / 平台 / 信任与说明）→ 可信信息（AI 辅助判读免责、不能替代执业医师、
   模型与权重可追溯、版权、返回顶部）。
2. **只为真实存在的页面建链接**。没有实现的隐私政策、法律声明、联系方式、
   社区或支持中心，**不得凭空创建假链接**。
3. 原有 `SiteFooter` 的规格信息按真实性与信息优先级**重新排布，不得无故删除**。
4. Light 页面下：深海蓝区块与浅色主体形成**明确但柔和**的过渡；
   Dark 页面下：仍需有**独立的明度层级**，不能融进主体背景消失。
5. 手机端合理折叠为单列或双列。返回顶部**尊重 reduced-motion**
   （用户要求减少动画时不强制平滑滚动）。
6. 已有页面的 `sections` 锚点**必须继续工作**。

**边界**
优先扩展现有 `SiteFooter`，采用 Brand 变体；
**不能因为首页升级而破坏其他页面的 Footer**。页脚不需要额外 GPU 特效。

**验收**
Footer Light/Dark 全图、手机端布局、**所有导航链接逐项验证**、
免责信息完整、返回顶部有效、与 Header/Hero 品牌语言协调、无假链接。

### R2-04 · Full-page Brand Unification

**目标**
消除"上半页是 Iris 2.0 钴蓝光学品牌，下半页却回到旧版骨白/暗房仪器风格"的断层。

**原则**
不是把整页涂成蓝色，也不是把每个区块都变成圆角玻璃卡片。
通过**银蓝品牌画布 + 白色或半透明内容区 + 深海蓝反相展示区**、
一致的排版与版心、节奏化留白、统一的品牌交互组件与适量材质层次，
实现丰富但协调的品牌体验。

**范围**
1. **逐区迁移**，不是一次性替换所有全局 CSS。先分析各区现有
   `.is-field` / `.is-dark` / `.is-night` 与品牌令牌的关系。
2. **必须保留的现有内容**：ScrollExpand 眼底影像示意、八类判读覆盖信息、
   样本与交互内容、分析流程、判读记录展示、Agent 产品入口、医学能力边界、
   产品 CTA、Footer 章节索引、已有真实交互 / 路由 / 免责声明与数据来源说明。
   **禁止为了"极简设计"删掉已存在的业务内容。**
3. **保留需要稳定深色观察画布的影像展示区**（ScrollExpand 的判读舞台）。
4. 首页下半页若需要新的品牌作用域，用**清晰、受控的场景命名**并同步设计规范；
   **不把 `.iris2` 无差别套到管理端、Agent 工作台或 Clinical 页面**。

**验收**
- 首页从 Header 到 Footer 的完整截图；**全页不存在突兀的品牌色或材质断层**。
- 主要内容仍可读可操作；所有章节跳转正确；ScrollExpand 仍可正常展开。
- Light / Dark 具有一致的品牌辨识度。
- 移动端没有文字遮挡、图片裁切错误或横向滚动。
- 页面完整内容及免责声明无缺失。

- 光学材质必须提供**改动前后同尺度对比**，不能只给最终截图。

  离屏/标签页隐藏、StrictMode 重复挂载、路由离开后返回、主题切换——
  **十条动效/WebGL 路径**逐条验证。
- 品牌层对比度断言（`tokens.contrast.test.ts`）保持绿。
- 键盘走查：导航与所有 CTA 可达、焦点可见。
- 包体不显著增长（首屏已是 +80.9 kB 字体；导航与卡片应基本为 CSS 成本）。

**R2 的风险**
首页两种底色共存是**当前已知状态**，改它会牵动 `index.css` / `app.css` 的语境类，
可能出现浅色/暗色对比回退。**每个区块单独迁移、单独截图**，不整页换。
共享 `SiteHeader` / `SiteFooter` 的改动尤其要回归管理端与临床页。

## R3 · 管理端 F+G · 成熟 SaaS 视觉

**目标**
管理台从"旧 B 档（0 圆角、墨色主按钮）"升级到 `DESIGN.md` §2.2 的目标外观。

**前置**
R1 已合。**不依赖 R2**（管理端与首页不共享语境类）。

**范围**
1. **新增 `.is-admin` 语境类**（第 2 层场景语境）：管理面底色、面板材质、
   品牌色主操作的取值来源。组件只消费上下文别名，不改组件逻辑。
2. **形状与层次**：卡片圆角 8–12px、实体卡片 + 极淡墨色阴影、发丝描边；
   去除多重内嵌容器；沿用现有 `--shadow-overlay` / `--shadow-modal`。
3. **主操作色**：钴蓝 `--brand-primary`（当前是墨色/信号橙）；
   信号橙退回"当前态/重点"本职。
4. **暗色主题**：深海蓝背景与分层面板；图表系列亮度单独调整；
   **不把所有 KPI 渲染成发光渐变**。
5. **图表口径与第二通道**：`--viz-series-*` 上线；每个系列配读数表 / 条端直标 /
   图例 / 线型之一；tooltip 与 `aria-label` 带系列名；
   **全量 / 时间窗口 / 分页**三种口径写在标签上。
6. **表格**：`DataTable` 的表头 `aria-sort`、排序只在后端支持时出现、
   分页口径文案（"本页 N / 全量 M"）。
7. **弹层**：Modal / Drawer 已是 Base UI；本阶段只做**视觉变体**（圆角 8px、
   墨色半透明遮罩而非纯黑、面板表面层次）。

**不做**
- 不自研排序 / 焦点陷阱 / Dialog / 图表——TanStack Query / TanStack Table /
  Recharts / Base UI 已就位（简报 §2.2 明确要求）。
- 不把首页 Beams 铺到管理页面。
- 不虚构 KPI（概念稿里的营收、准确率一律不进）。
- 不改后端端点。

**验收**
- 7 个管理页 × 4 档宽度 × 亮暗截图。
- **切时间窗立即失效 + 占位**的回归用例保持绿（`AdminDashboardPage.test.tsx`）。
- 图表的第二通道与口径标注逐图核对。
- 对比度：正文 ≥4.5:1、图形 ≥3:1，亮暗两套都实测。

**风险**
管理端页面多、状态多（加载/空/错/无权限），改语境类容易让某些状态回落到根级
令牌。**逐页截图，不批量替换类名。**

## R4 · Intelligence H+I · 协作台与影像工作台

**目标**
从"一个聊天框"变成"看得到协作的工作台"。

> ⚠️ **本阶段协议先行，界面在后。**
> 后端当前只有 `assistant / reasoning / tool-request / tool-response / confirm`
> 与终态 `event: "done"`。多 Agent 编排、任务依赖、运行态推流**都不存在**。
> **在协议定下来之前，界面上一行都不许画假状态。**

**前置**
R1 已合；**且**后端事件契约评审通过（单独 PR，不在本路线图里夹带）。

**阶段拆成三小步，各自独立 PR**

| 小步 | 内容 | 前置 |
|---|---|---|
| R4.1 | **事件契约**：定义 `runId, agentId, stepId, status, tool, evidenceRef, timestamp`；后端产出真实事件；前端只做**日志式**事件流（不做节点图） | 后端契约评审 |
| R4.2 | **协作视图**：Agent 节点与状态、工具调用、时序、任务依赖；运行态动效绑定真实事件 | R4.1 |
| R4.3 | **影像工作台**：主画布（中性深色，任何主题）、双眼对比、缩放平移、标注/疑点、影像质量提示；证据区结构化 | R4.2 + 影像数据通道 |

**范围要点**
- **影像画布中性深色**：任何主题下都用稳定中性灰阶，不染品牌蓝、不发暖光。
- **四套语义分离**：运行态（品牌蓝/冰青）、智能体类别（局部紫）、
  待人工复核（独立审查状态）、临床严重度（`--risk-*`）。**"高风险"绝不能用紫色渐变。**
- **对话区是子区域**，不是全屏唯一内容。
- 证据区必须有：模型版本、工具来源、影像来源、引用证据、置信度与限制、
  复核与来源标注、免责。

**不做**
- 不复制心脏扫描 / 生命体征 / 急诊队列等非眼科语义。
- 不引入基因合成、3D 生物模型等非本产品领域概念。
- 不为沉浸感盖住影像或降低可读性。
- 不自研 SSE 客户端、不另造编排引擎。

**验收**
- R4.1：SSE 事件有**录制回放**测试；前端事件流与真实事件一一对应。
- R4.2：状态语义四色不混用（对照度 + 视觉走查）；reduced-motion 下运行态降级为静态标记。
- R4.3：影像画布在 Light/Dark 下都做中性灰阶校验；标注与病灶对比度实测。
