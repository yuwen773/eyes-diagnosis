## 第 4 轮：把「预览就是公开页那篇文章」变成可核对的事实

上一轮视觉复审指出：手机档预览不是公开页的手机版式——设备框只有
`container-type: inline-size`，而 `news.css` 里标题字号、纸面内边距、目录与正文
间距都是 `vw` 派生的，**vw 仍按浏览器视口算**，于是 390px 的设备框拿到的是 1440
视口的尺寸。断点补上了，尺寸没补。

这轮的改法不是再写一套样式，而是**让同一批尺寸在两种上下文里各自成立**：

| 位置 | 公开页 | 管理端预览设备框 |
|---|---|---|
| 标题字号 | `--news-scale-title: clamp(32px, 4.2vw, 56px)` | 同一变量覆写为 `clamp(32px, 4.2cqi, 56px)` |
| 纸面内边距 | `--news-scale-paper-pad: clamp(26px, 3.4vw, 52px)` | 覆写为 `3.4cqi` |
| 纸面量宽 | `--news-scale-paper-max: clamp(52px, 6.8vw, 104px)` | 覆写为 `6.8cqi` |
| 目录与正文间距 | `--news-scale-body-gap: clamp(24px, 3.6vw, 56px)` | 覆写为 `3.6cqi` |
| 眉线 / 封面纵向留白 | `--news-scale-head-pad` / `--news-scale-plate-gap`（vh 派生） | 覆写为 `calc(var(--news-sim-vh) * …)`，模拟视口高度写明（桌面 900 / 手机 844） |

`1cqi` = 设备框宽度的 1%，与 `1vw` = 视口宽度的 1% 等价——**设备框多宽就等于模拟
多宽的视口**。公开页的值逐字未变（仍是 vw/vh），公开页外观零变化。

核对脚本 `admin-news-preview-parity.mjs` 用**同一篇文章**（库里已发布文章）在两个
上下文里量计算样式，逐项比对（容差 0.6px），本轮退出码 0：

| 量 | 手机档：公开页 390 视口 | 预览 390 设备框 | 桌面档：公开页 1020 视口 | 预览 1020 设备框 |
|---|---|---|---|---|
| 标题字号 | 32px | **32px** | 42.84px | **42.84px** |
| 眉线上下内边距 | 25.32 / 30.38px | **25.32 / 30.38px** | 27 / 32.4px | **27 / 32.4px** |
| 纸面内边距 | 26 / 18px | **26 / 18px** | 34.68px（四边） | **34.68px** |
| 目录与正文间距 | 24px | **24px** | 36.72px | **36.72px** |
| 正文列数 | 1 | **1** | 1 | **1** |
| 标题文本 | 角膜炎的症状、原因与治疗 | **同** | 角膜炎的症状、原因与治疗 | **同** |

对应截图：`parity-public-mobile.png` / `parity-preview-mobile.png`（390）、
`parity-public-desktop.png` / `parity-preview-desktop.png`（1020）。

## 已知取舍

1. **眉线按发布状态走**：只有 `status=1`（已发布）才沿用真实发布时间；草稿 / 待审核 /
   下架即使带着 publishTime 也一律显示「预览稿 · 尚未发布，公开页不会出现」——
   旧逻辑看 publishTime 存在性，会让待审核 / 下架文章冒充「已上线」。
2. **摘要不是独立字段**：后端保存时按「剥标签后的正文前 30 字」生成摘要，表单里没有
   摘要输入框。预览显示的是**保存后将写入的**那 30 字，不足 30 字时如实说「保存会被
   拒绝」，不虚构一个摘要字段。库里老文章的摘要是当年手写/旧规则生成的，
   与「保存后摘要」不同时两者并列显示，不假装它们一样。
3. **预览时收起右侧发布设置栏**：编辑区两栏只有 676px，塞不下公开页 900px 以上的
   桌面版式。切到预览把右栏收起（与有没有未保存修改无关），提示语无条件写明这一点，
   保存按钮仍在工具行；右栏里的「未保存」读数因此在预览中不可见，未保存状态改由
   预览条单独一句「当前有未保存修改」承担。
4. **同宽即同版式（可核对）**：预览设备框宽度 = 模拟的视口宽度，断点与尺寸都按它算，
   因此「设备框 390px」与「公开页 390px 视口」逐项同值——由
   `admin-news-preview-parity.mjs` 量化核对，容差 0.6px。断点档位（900 / 768）
   与 `news.css` 的媒体查询一一对应。
5. **纵向留白按声明的模拟视口高度算**：文章眉线、封面下方间距原本是 `vh` 派生的，
   容器没有对应的纵向单位。预览里写明模拟高度（桌面 900 / 手机 844）并据此换算，
   不让它们继续按管理员浏览器窗口的高度变化。
6. **桌面预览宽度受管理端版型限制（如实记录）**：管理端 1440 视口下工作区主列约
   1020px（侧栏 248 + 管理端内边距），设备框再宽也受父容器限制——所以「桌面」档
   模拟的是 1020px 视口，不是 1240px。预览条实时写出当前模拟的宽度，别让人以为
   按钮写着「桌面」就一定是桌面宽度。组件与 CSS 与公开页仍是同一份。
7. **目录在预览里不吸顶**：预览画布没有真实滚动容器，`position: sticky` 无处可粘，
   目录一律 static（公开页桌面端是 sticky）。只影响目录的吸附，不影响版式。
8. **摘要读数口径**：显示「剥标签后正文前 30 个字符」，与后端 `buildSummary`
   同管线；Markdown 预览里 `&amp;` 类实体在渲染时被还原，字数与后端对已落库
   HTML 的统计最多差在实体字符上（`NewsArticleView` 文件注释有写）。
9. **字数按渲染后全文算**：Markdown 源的 `#`、`**`、`-` 记号不计入字数，与公开页
   「数库里存的 HTML」同口径；被提走的导语与挤出正文的标题仍在全文里，不多算
   也不少算（单测断言 402 / 483 两个真实读数）。
10. **同屏两个数字是两种口径，不是少了几十字**：文章眉线的「N 字」是公开页同口径的
    `newsWordCount`（汉字按字、拉丁按词）；编辑区那一侧的「N 字符」是后端
    「正文至少 30 字」守卫用的可见字符数（剥标签后的正文长度）。所以同屏 154 字符
    对 135 字是正常的——两边服务的目的不同。界面因此把编辑器侧一律写成「字符」，
    并在该读数上挂口径说明，不让两个「字」混在一起。
11. **作者兜底两侧不同**：作者取库里 `author` 字段（两侧同源）；公开页缺作者时
    显示「编辑部」，管理端预览显示「未署名」——预览面对的是还没发布的稿子，
    「未署名」比「编辑部」诚实。这是唯一的文案差异，不影响版式。
