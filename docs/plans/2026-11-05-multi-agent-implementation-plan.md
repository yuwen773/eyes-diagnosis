# 面向患者的多智能体诊断：实施顺序

> 状态：用户已确认架构方向；本文件是待评审的实施任务草案，不代表临床、生产或部署批准。与 PR #14 原 Graph 方案存在路线差异，合并或冻结前须统一。

## 目标和边界

患者上传眼底图片，Java 创建任务并调用现有 Python 诊断服务；Vision、Evidence、Explanation、Critic 四个独立 Agent 在协调层管理下协作，最终由确定性门控及必要的医生复核决定发布。患者单独授权后才能写正式记录。保留既有聊天与普通诊断入口；第一版的完整流程仅用于演示与工程验证。

参考 `docs/plans/2026-11-05-patent-multi-agent-evolution-adr.md` 的角色、权限、失败关闭和证据冻结契约。四 Agent 是用户要求；实现细节、正式持久化结构和 Graph 选型仍待验证。专利材料原件尚未核对，本文不声称满足具体权利要求或已验证临床有效性。

## 顺序和验收

### 0. 固定合同与基线

- 对照现有 Java 接口、Python gRPC 协议、数据库版本和用户可见流程，定义新增 API 和保留的兼容行为；确认真实身份与医生角色可用性。
- 固定示例输入、模拟模型/资料和隔离数据库，形成可重复的业务场景及禁止发布条件。标注真实服务、模拟服务与未验证范围。
- 确认领域术语、复核状态、证据和正式记录的外部行为；临床自动发布规则尚未由领域人员确认，默认等待医生。
- **验收**：对相同输入、重复请求、权限失败和未知状态的期望可由接口测试观察，不修改现有入口。

### 1. 协调与恢复 PoC

- 锁定当前 Spring AI Alibaba 版本，比较小型 Graph 编排与领域状态机，业务规则、调度器、测试输入与故障注入保持一致；调度器选型单独评估，不以框架宣传能力代替测试。
- 在隔离数据库验证业务状态与后续任务登记的提交/回滚；对于 Graph 验证 Saver 的真实写入协议、事务协调、序列化、中断和跨进程恢复。
- **验收**：提交前后崩溃、重复领取、旧执行者返回、进程重启与版本不兼容有可重复断言；失败时不发布、不重复写正式记录。PoC 失败则修订方案，不冻结 Saver DDL。

### 2. 任务与推理底座

- 新增独立诊断任务和状态、身份归属、不可变输入版本与摘要、Python 推理快照、版本 CAS、事件及受控任务执行；gRPC 结果必须与输入绑定。保留已有入口。
- 质量失败、模型失败、拒识及未知状态走受限路径；校准/OOD 占位状态不当作有效的临床可靠性证明。
- **验收**：真实或隔离 Python 服务明确标识；同一任务与重复请求、服务超时、旧执行者返回和重启不产生不一致结果。环境未就绪的真实服务测试标为未运行。

### 3. 受控资料

- 建立最小上传、审核、疾病/主题标注、版本及撤回流程；复用现有向量、BM25、RRF 和 rerank 的底层能力，但资格过滤与结构化引用独立于普通聊天 RAG。
- 管理员与领域审核人员权限分离；测试资料和真实审核资料明确标识。发布与保存前重新校验冻结的文档版本、治理版本及片段摘要。
- **验收**：私有、未审批、撤回、不匹配及版本变化的资料不得成为可发布证据；审核与撤回的并发不允许旧资格绕过保存门禁。真实资料须由指定领域人员审核。

### 4. 四 Agent 协作

- Vision Agent 使用现有分类与质量信息并记录再分析建议；Evidence Agent 调受控检索；Explanation Agent 产出分层草稿；Critic Agent 给出可定位异议。每个角色具备独立上下文、工具权限、版本化结构化输入输出和审计。
- 协调层检查消息绑定、超时与权限。每任务最多补证一次、重写一次，另有总调用及耗时上限；新证据集重新冻结。M1 不执行图像增强或重推理。
- **验收**：模拟推理与证据的端到端协作测试覆盖证据不足、格式错误、Agent 超时、异议、预算耗尽和来源撤回；Critic 不能单独放行。固定数据集比较单 Agent 基线及逐 Agent 消融，记录引用正确性、无依据声明、遗漏、耗时和成本。

### 5. 医生复核、患者展示与保存

- 提供经授权的最小医生待办和通过/不通过操作，绑定冻结结果；不通过保留原因与版本，不能自动发布。自动发布条件未经临床领域人员确认前默认等待医生。
- 患者查看业务进度、受控的 Agent 工作摘要和获准发布的分层解释；围绕发布结果追问不改变诊断、复核或保存状态。患者单独批准后，确认状态、正式记录和唯一回执原子提交。
- **验收**：医生越权、自审、重复决定、医生不可用、患者跨账号及重复批准、复核后来源撤回和保存竞争均有端到端断言；页面不显示未获准的诊断推测或草稿。

### 6. 图像反馈与多模态研究（后续）

- M2 研究受限预处理和新推理 epoch，保留原始结果，安全拒识与人工处理优先；独立数据验证有效性后才考虑启用。
- M3 研究视觉特征输出、跨模态对齐及索引；与现有文本混合检索对照 Recall@K、nDCG 和来源有效性，不能仅凭向量拼接宣称对齐。
- 临床评价、真实患者数据授权、生产部署和专利原文核对分别设独立门禁。

## 阶段纪律

采用隔离环境和可复现测试，迁移只新增且避免版本碰撞；不将密码或本机连接事实写入仓库。先完成阶段验收再扩展；失败、外部依赖未就绪和未运行测试明确报告。提交、推送、合并、生产数据操作和部署遵循各自授权。
