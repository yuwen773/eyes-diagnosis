## 1. 目标与边界

保留 Vue 前端，将业务后端、算法和 Agent 完整纳入 Python 项目。最终支持的开发、构建、测试、数据库升级、部署和运行链路均不需要 Java/JVM、Maven、Tika JAR 或 Spring Session 服务。

保留现有 MySQL、Redis、Chroma、COS 等集成与数据归属，不因语言迁移更换业务存储、embedding 模型或向量维度。允许非 JVM 本地解析程序与 Python 本身的原生依赖；“去 Java”不等于要求所有依赖都用 Python 编写。

Windows 支持本地开发，Linux 支持容器化部署与 CI，主要交付 Compose 编排。维持既有 Python 3.11 验证基线，先建立根目录 Python 工程入口、依赖和运行说明，尽量保留现有模块路径；不把全面目录重构混入本轮迁移。

用户账号、稳定 ID、密码、角色、诊断记录、聊天、知识库及未完成任务须保留。用户保存授权、医生复核和冻结的 AI 来源继续相互独立；工程验收不等于临床验证。

## 3. 身份与前端契约

Python 接管 `/api/user/login`、`/api/user/logout`、`/api/user/get/login`，移除逐请求回调 Java 和 `java_base_url` 等活跃配置。复用集中鉴权接口，所有业务及 SSE 路径继续通过服务端身份与权限检查。

- Cookie 只携带随机会话标识，Redis 使用独立于 Spring Session 的命名空间；不得解析或覆盖旧 Java 序列化对象。
- 登录校验保留 BCrypt 与既有遗留 MD5 的兼容规则及升级语义；响应不得包含密码或哈希。
- 逐请求核验会话和当前用户状态，保留登出、过期、删号及角色变化的失效行为；Redis 不可用时不能绕过鉴权。
- 登录时轮换会话标识，登出撤销对应会话。Cookie 的路径、过期、HttpOnly、Secure、SameSite 和开发/部署同源配置需形成明确配置及测试，不隐含依赖 Spring 默认值。
- 切换后旧 Cookie 不取得 Python 登录资格，用户以原账号密码重新登录；不因重新登录清空聊天或任务。
- 保留旧 API 的 `code/msg/data`、Long 字符串、分页和日期约定及 `40100` 登录引导；新工作流的 HTTP 202、401、403、409 等契约仍独立。
- Vue 保持现有风格，只做新身份接线、旧任务视图与关联重建等必要改动。OpenAPI 生成来源改为 Python，须验证生成后页面仍工作。

既有旧缺陷记录继续保留，不把去 Java 当成修改新闻、日期等既有行为的授权。

## 4. 数据库历史与数据承接

旧 V1–V22 SQL、bootstrap callback 和 Flyway 历史保留审计依据。移除 Java 目录前，将仍需保留的 SQL 按原字节移动至独立迁移资产目录并记录摘要；不得因删除 `src/` 丢失数据库资源。

Python 新迁移链使用自己的历史记录。既有库只有在旧历史、关键 schema 与数据约束核验通过且完成必要升级后，才登记承接基线；不得仅凭表存在、手工标记版本或 ORM `create_all()` 宣布承接完成。

- 空库：在无 JVM 环境完成建库结构初始化、新迁移链登记及后续升级；SQL 顺序与 callback 效果须明确。
- 既有库：先只读核验版本、checksum、schema 和数据归属，保留原历史不重放已应用的非幂等 DDL；必要升级在备份与维护步骤内执行。
- V8 已知 checksum 分歧、未知版本、失败历史或结构漂移：输出明确阻塞与差异清单，不自动 repair、删除历史行或改写 checksum。
- 分别准备空库、代表性旧库及 V22 交接快照，验证升级路径。只支持明确验证的起点，未知状态停止并要求专项处理。
- 以稳定 ID、数量、关系、关键业务内容和批准/复核记录验证承接，不能只看建表成功。
- API/Worker 启动不隐式执行 DDL。升级是独立、可审计的部署步骤；并发升级须受控。

选定 Python 迁移库与版本前需验证上述路径；最终交付的初始化、交接和升级入口不得需要 JVM。

## 5. 三类诊断数据及恢复

| 类别 | 迁移后的要求 |
|---|---|
| 已保存的传统诊断记录 | 按原 ID、用户归属、AI 与人工字段继续读取，不猜测其工作流关联 |
| 当前 Python 未完成工作流 | 保留原输入、checkpoint、pending writes、审批/补充/保存等待和审计；重启后按原版本恢复 |
| 旧 Java 未完成任务 | 完整保留原数据，提供按归属鉴权的只读视图和明确的旧版标记；不反序列化续跑、不伪装成功 |

当前 Python 恢复依赖 graph version/hash/action version；图哈希来自导出结构与 action version，不直接来自源码路径。目录搬迁不必然改变哈希，但不能仅凭“节点逻辑没变”宣称兼容：须核验导出结构、状态含义与实际恢复。对已经持久化的代表性任务做升级前后及跨进程验证；若确需改变版本，须明确兼容或迁移策略，不能让任务静默失去恢复能力。

恢复样本须覆盖医生质量复核、最终复核、保存确认与聊天补充等待。聊天补充另有独立图版本校验，不能只验证诊断主图。新增来源任务关联字段若不改变图行为，可以独立迁移；若改变节点输入或状态语义，须另行判断恢复兼容性。

旧任务的关联重建是新能力：用户查看旧记录后明确确认，创建独立的新任务，记录原任务 ID、用户、发起时间和审计关系；重试须幂等，跨用户请求拒绝。原输入无法可靠复用时要求重新上传，不把缺失输入或旧模型结果当成新任务已完成。旧任务原记录不被新结果覆盖；医生复核与保存授权重新执行，不沿用旧批准。

当前代码不能保证旧任务可以通过原工作流查询或复核接口读取，因此只读适配和关联记录必须实际实现并通过 HTTP/UI 验证。

## 6. 无 JVM 文档解析与知识库

移除 Tika JAR 的安装、下载和执行入口。选用明确支持 Windows 与 Linux 部署要求的非 JVM 本地解析工具，由 Python 适配；固定版本与来源，记录可校验的产物，设置子进程边界、超时、编码和清理规则。不得在上传请求中临时下载工具。

DOC 与 DOCX 分开验收：二进制 DOC 需使用代表性的真实中文正文、表格、页眉页脚以及空白、损坏、加密和伪装文件；DOCX 保留现有合并/嵌套表格与页眉页脚断言。具体工具若无法满足必要样本，则更换方案或报告阻塞，不降级为静默丢弃内容。

验证链为上传 → 解析 → 分块 → 索引 → 归属过滤 → 检索与引用。保留原 collection、chunk ID 约定、metadata 类型、embedding 模型及维度；不得无授权清空、重嵌入或更换集合。受控 embedding 可验证编排与访问隔离，不能证明真实语义召回。

## 7. Python 工程、CI 与部署

建立根目录 Python 工程与可复现依赖入口、Windows 启动说明、Linux 容器构建和 Compose 编排。API 与 Worker 是独立进程，共用既有业务数据；前端静态产物经入口服务访问 API。Compose 可连接既有 MySQL/Redis/Chroma/COS 配置，不自动清空或重建现有数据。

将读取 Java 控制器/枚举源码的 Python 测试替换为独立的冻结契约、HTTP 断言和必要的数据快照。移除活跃 CI 的 Java setup、Maven、Flyway、Tika 安装及 Java 验收探针；真实服务验证改为 Python 登录、纯 Python 升级、独立 API/Worker 与真实 MySQL/Redis/Chroma。

依赖扫描覆盖配置、脚本、文档中的当前运行命令、容器层、生成器和测试入口，不能仅删除 Java 目录。尤其替换 `verify_worker_concurrency.py` 的 JDK/Maven 升级入口，更新主 README、项目指引和 OpenAPI 生成入口；仍依赖原 `application.yml` 与 SQL callback 路径的测试也需迁移。历史文档、旧证据与标签中的 Java 描述保留历史身份，不作为活跃依赖。Python gRPC/MCP 等无 Java 的独立能力是否保留按当前调用关系处理，不扩大清理范围。

Linux 无 JVM 容器运行全链路；Windows 验证开发、测试及 DOC 工具无需 Java，PowerShell 命令与脚本使用 `pwsh.exe`。持久数据、临时验收库、运行日志和用户原有未提交文件不因工程整理被删除或混入提交。

## 9. 切换与回退

维护窗口先阻止新业务写入、上传和新执行，停止新增任务领取并安全处理在途租约；人工等待任务持久保留，不要求等所有用户完成审批。记录数据库、向量、对象引用与运行版本的一致性备份和清单，再升级、启动纯 Python API/Worker、切换路由并验证。

恢复业务写入前，实际验证旧数据访问、重新登录、当前 Python 等待任务恢复以及旧任务视图；使用隔离验收数据检查写路径。失败时停止新进程，按演练步骤回退已保存的旧发布与路由，不擅自覆盖新数据。此阶段临时使用旧 Java 的授权仅适用于用户确认的首次回退边界。

一旦恢复业务写入，不得直接切回旧 Java 或恢复旧备份覆盖后续记录。发生故障先止写、保留新增数据与审计，按经过验证的兼容 Python 发布回退或向前修复；首个纯 Python 发布没有更早的纯 Python 版本时，须明确采用止写与向前修复，不能虚构可用回退包。

后续常规发布与回退只依赖 Python。数据库回退以保留数据与兼容的增量 schema 为原则，不用删表、清空向量或倒退历史替代应用回退。

真实业务库升级、生产切流和清理不由本次设计讨论直接执行。首次生产切换仍需基于完整演练结果作出具体发布决定。

## 10. 完成判据与证据层级

- **无 JVM 工程门禁**：最终项目在支持环境无需 Java/Maven/Tika/Flyway 即可安装、构建、初始化与升级、测试、启动及部署；删除 Java 后重新验证，测试不读取 Java 源码。
- **身份与契约门禁**：真实 Redis 会话的登录、轮换、登出、过期、角色/删号失效、服务异常及多用户隔离通过；旧业务、SSE 与新工作流各自契约正确，Vue/OpenAPI 构建与关键交互通过。
- **真实基础设施门禁**：在隔离的真实 MySQL、Redis、Chroma 上执行 API → Worker → 持久化/重启链，验证事务、租约、fencing、版本冲突、幂等、人工等待与明确批准后仅一次保存。
- **数据与恢复门禁**：旧库承接与空库初始化通过；稳定 ID、数据归属、内容及审核/授权来源保留；当前 Python 任务能恢复，旧 Java 任务可查且关联重建不继承批准。
