# ADR：面向患者的眼底诊断多智能体协作演进

> **状态：讨论草案，待用户确认整体共识，未冻结。** 本文记录已讨论的方向，不授权实施、迁移、临床应用或部署。与既有架构稿存在范围差异时，先评审并同步决议；不能把两个候选稿同时视为已冻结规范。

## 背景与依据

目标是让患者获得以 Python 眼底图片推理结果为基础、有受控来源、分层展示且可追溯的辅助说明，并通过多个职责独立的 Agent 协作。用户已确认图片分类与风险门控由业务服务控制、证据由受控服务提供，医生复核、发布与患者保存授权不能由 Agent 决定。

用户提供的专利摘要提出不确定性触发图像处理反馈、多模态检索与协作解释等方向；本工作树未发现所述权利要求书、说明书及附图原件。**具体权利要求编号、保护范围和本设计与专利的一致性均待原文逐条核对**；本文不是法律意见，也不宣称已实现专利或验证临床有效性。设计可先探索，不因原文不可得而推断技术效果。

当前代码事实：`src/main/proto/diagnosis.proto` 的 `Diagnose` 返回 `top_predictions`、质量、拒识、校准、OOD、模型和预处理版本等字段，未提供视觉特征向量或可调预处理请求；`EyeImageAnalyzerTool` 使用多模态模型生成结构化文字，不能等同于模型视觉特征。`DocumentSearchTool` 已有向量、BM25、RRF 与可选 rerank，但按用户过滤，输出格式化文本，不是已获准的临床证据链。当前校准配置为 `NOT_CALIBRATED`，gRPC 当前返回 OOD `NOT_EVALUATED`；不把这些占位状态当作合格的校准或 OOD 检测。上述是静态事实，运行能力及生产配置另行验证。

## 决策范围与原则

- **真实多 Agent 是目标**：每个 Agent 具备独立职责、上下文、允许工具、结构化输出和可观察调用；多个普通处理节点不自动构成多个 Agent。优先复用现有 Spring AI / Spring AI Alibaba，不新增第二套 Agent 框架。
- **领域服务掌握业务真相**：Python 分类服务负责图片推理；Java 负责校验、状态、证据资格、风险规则、人工决策与发布。Graph 与领域状态机是待验证的实现候选，不预先决定引擎或是否采用调度器。
- **Python 作为已有实现和安全经验参照**，不要求逐节点或逐表复制；保留医生复核与患者授权分离、证据冻结和复验、禁止未授权正式保存、失败关闭及可追溯等不变量。任何对当前 API 或用户可见行为的改变需单独评审与兼容计划。
- 本 ADR 作为 PR #14 原设计的**备选战略方向**，不会自动替换已评审契约、批准 PR 或冻结 17 张候选表。

## 目标路径和权力边界

```text
患者上传 → Java 输入校验/任务登记 → Python 图像推理 → 确定性质量与风险门控
        → Evidence Agent → Explanation Agent → Critic Agent
        → 确定性校验/证据复验 → 按规则医生复核 → 发布 → 患者单独授权保存
                         ↑ 可在规则约束下补证或重写一次
Vision Agent（M1）→ 汇总结果并提出再分析建议（M1 仅记录）
M2 候选：策略服务审批 → 受限预处理 → Python 重新推理
```

门控可在任意不满足条件的阶段停止或进入受限状态，不保证上述所有节点对每次任务均执行。图片不合格、模型失败或安全拒识时不生成正常疾病解释；等待医生时仅展示业务规则允许的状态和提示。患者可对已发布内容追问；一般眼健康信息须与本次诊断区分，追问不能改变诊断、复核和保存状态。

| 角色 | 输入与权限 | 输出及不能做的事 |
|---|---|---|
| Evidence Agent（M1） | 仅消费获准暴露的推理摘要和疾病/主题范围；调用服务端绑定身份与范围的受控检索工具 | 引用证据包、来源标识、片段、版本和不足之处；不能审批或扩大资料资格，无法找到足够证据则受限 |
| Explanation Agent（M1） | 获准展示的推理结果、风险状态、冻结证据；无任意外部检索或写权限 | 患者分层解释草稿与引用；不得确诊、虚构证据、覆盖医生决定或自行发布 |
| Critic Agent（M1） | 独立上下文，读取同一冻结输入及草稿；只读 | 结构化异议、具体引用及可定位理由；意见不等于合规证明，不能代替医生或安全门控 |
| Vision Agent（M1） | 使用现有分类和质量能力，读取推理结果及获准质量指标 | 结构化分析及再分析建议；M1 仅记录建议，不执行图像再分析；不能确诊或自行改变图片 |

受控 RAG 的资格必须由服务端校验：非删除、启用、`CURATED_PUBLIC`、`APPROVED`、疾病及主题匹配；冻结文档版本、治理版本和片段摘要，发布、医生确认和患者批准保存前复验。聊天私人知识库和模型已有知识不能自动提升为临床证据。Agent 复核结果只能增加拦截信号，不能放宽确定性规则。

患者界面采用两层：首层展示业务允许的主要发现、风险提示、下一步及不确定性；展开层展示可公开的分析细节、依据和限制。患者还可看到由后端按状态及已校验结果组织的简要 Agent 工作说明。校验失败最多重写一次；使用当前获准输入和冻结证据，补证时先另建并冻结新证据集。来源失效立即停止，再次失败则不展示草稿，记录原因并按门控进入受限或人工处理。

第一版提供最小资料管理：管理员上传，领域审核人员确认疾病与主题后方可作为患者解释依据；撤回后阻止后续发布或保存。沿用现有模型服务需符合用户授权与环境策略，仅传任务所需数据，图片及身份信息的发送范围受控并记录。医生不通过时保留决定和原因；医生不可用或自动发布条件未由临床领域人员确认时继续等待，不因超时自动放行。

## Agent 通信契约（候选）

每条消息由协调层签发和校验，最小字段：`workflowId`、`workflowVersion`、`executionId`、`attempt`、`senderRole`、`recipientRole`、`schemaVersion`、`inputReferences`、`outputReference`、`evidenceSetDigest`（如适用）、`status`、`reasonCodes`、`traceId`。敏感数据只传必要引用和受控片段，不在普通日志记录原图或患者自由文本。输出必须经 schema 校验；禁止 Agent 自行指定用户身份、证据可见性、审批结果或工具权限。

Evidence 输出应含引用 ID、文档/治理版本、片段及摘要、疾病与主题、证据不足标志；Explanation 输出包含分层内容、逐条声明到引用的映射和不确定性；Critic 输出包含问题类型、草稿位置、关联输入、原因及建议动作，严禁单一 `approved=true` 作为放行凭据。协调层验证消息版本、输入绑定和权限；超时、格式错误、来源缺失或绑定冲突 fail-closed，落审计并按有界重试策略处理。

## 有界反馈与溯源

M1 只允许规则授权的补证或草稿重写：每个诊断任务最多自动补证一次、最多自动重写一次，并设总耗时和模型调用上限。补证形成新的候选证据集，重新冻结、生成和复核；不得覆盖原冻结快照。程序判定来源失效时停止，不得用新来源静默替换冻结集合。保留每次模型调用、证据版本、审查意见及最终门控原因；外部 LLM 可能重复执行，数据库结果靠幂等键、版本 CAS 和事务防重，不能声称供应商端 exactly-once。

M2 再分析属于实验候选：规则服务以图像质量、模型状态、Top-1/Top-2 差值等**已验证特征**判断是否可触发，Agent 的建议不能直接执行。预处理策略由服务端白名单、固定参数范围与总次数上限约束；每次生成新图像身份、输入摘要、预处理版本和新推理 epoch，保存原始图及全部推理快照，不覆盖原结果。风险升级、结果冲突或质量异常时停止并要求人工处理；不允许模型自己选取最有利的结果作为最终输出。差值不是临床可靠性，未经校准和独立验证不得展示为可靠性评分。

## 分阶段门禁

| 阶段 | 候选交付 | 进入下一阶段前的验收 |
|---|---|---|
| M0 底座 | 锁定外部行为和安全不变量；隔离 PoC 比较 Graph 与领域状态机，可靠调度独立评估 | 同一组提交前后崩溃、旧执行者返回、并发领取、重复人工决定/保存、来源撤回及身份检查通过；正式 Saver DDL 必须先有锁定版本运行时证据 |
| M1 四 Agent 协作 | Vision、Evidence、Explanation、Critic 与受控检索、分层草稿及审计；Vision 建议仅记录 | 结构化消息和权限边界可测；证据不足与撤回 fail-closed；同一固定样例对比单 Agent 基线及逐项移除 Agent；报告无依据声明、引用正确性、遗漏、患者可读性、耗时与成本；不宣称临床有效 |
| M2 再分析反馈 | Vision Agent 提议，规则服务执行白名单预处理与有界重推理 | 独立数据集比较原图基线与增强方案，按疾病、质量、设备和人群分层，报告准确性、敏感度、特异度、拒识率、预测冲突和安全退化；未达到预先评审标准不得启用 |
| M3 多模态证据 | 评估视觉特征接口、跨模态对齐及兼容索引，结合现有文本混合检索 | 固定语料、标注集及数据切分，对比文本检索、融合及消融的 Recall@K、nDCG 与受控来源有效性；视觉与文本向量不可假定同空间，禁止仅拼接即宣称对齐 |
| M4 协作完善 | 评估更复杂的规划、冲突处理、复核与运行可靠性 | 预注册或预先冻结测试集、指标及阈值；对照和消融、医生与患者代表评估、跨进程故障注入及独立临床验证按各自门禁完成 |

各阶段均保留版本化数据、分母、失败样本与未完成项；任何离线或模拟测试不替代临床、生产、真实服务或人体验收。具体指标阈值及数据治理须在实验前与领域人员确定，不从结果反向选择。
