# 患者授权保存正式诊断记录（#22）

对应 [#22](https://github.com/yuwen773/eyes-diagnosis/issues/22) 和父规格 [#15](https://github.com/yuwen773/eyes-diagnosis/issues/15)。医生复核、患者查看和患者保存授权相互独立。既有聊天及普通诊断入口继续使用原行为。

## 患者操作

在患者任务页打开获准说明，选择“查看拟保存内容或查询回执”。后端重新验证来源、医生决定及冻结材料，返回本次拟保存的完整患者说明，页面以它替换原说明。阅读主要信息、风险、下一步及可展开的依据与限制后，患者勾选同意并选择“同意并保存”。未批准前只有授权候选，不创建正式记录。

每个任务一份授权候选，有效期为准备时起 30 分钟；请求必须带回实际查看的授权 ID、任务/草稿/证据版本及内容 SHA-256 摘要。过期或冻结材料失效后成为 `RESTRICTED`，本期不提供同任务重新冻结或续期接口，需人工处理或新任务。请求本身带错版本返回 409，不覆盖原候选。

保存失败或网络中断时清理页面的旧内容及勾选状态。重新打开任务并查询保存状态与回执，可确定是否已提交；重复批准不新建记录。切换任务、刷新、切换账号后丢弃迟到响应。

## 事务及冻结门禁

V14 新增 `t_patient_authorization`，保存患者可见内容快照、版本、摘要、有效期、授权状态、正式记录 ID 和唯一回执；`t_diagnosis.patientTaskId` 的唯一约束阻止同任务重复记录，不修改旧记录。患者仅能访问本人任务，角色不会赋予跨账号保存或查询回执的权限。

保存复用 #21 的完整门禁，在同一 DataSource 事务内按来源 → 任务 → 医生复核及冻结材料 → 授权行的顺序持锁。门禁验证输入绑定、推理安全、草稿结构、引用和协作材料，并复验文档/治理版本、范围、片段及资格。行锁保持到正式记录、授权状态和回执共同提交；任何写入异常均回滚。来源撤回与保存串行化，若撤回先提交则拒绝保存并持久化受限状态，历史医生决定保持原样。

授权快照及摘要同时覆盖完整分层说明、来源和拟写入正式记录的模型疾病、原始概率。页面在批准前明确展示模型疾病和概率，附概率不代表临床可靠性及“模型预测并非确诊”提示。正式记录从已确认快照取疾病和概率，同时保持既有历史接口的 `confidence`/`probability` 映射；完整分层说明及来源以回执和任务绑定追溯。私有对象键不转为公开图片 URL，内部 Agent 输出、推理及医生意见不会写进患者历史文本。未从患者授权推导新的医生确诊结论。

并发批准按任务串行，只创建一条正式记录和一个回执；已提交授权是历史事实，相同版本重试和状态查询回放原回执，即使来源后来撤回或候选有效期已过。回放仅返回回执元数据，不重新发布失效的说明或引用。

## HTTP 接口

路径带 `/api` 前缀，使用 `BaseResponse` 和 `Cache-Control: no-store`。不存在或非本人任务返回业务 `40400`，未登录 `40100`，请求字段缺失 `40000`，内容冲突或禁止保存为 HTTP 409、`40900`。Long 遵循现有字符串序列化。

| 方法与路径 | 用途 |
|---|---|
| `GET /diagnosis-tasks/{id}/save-authorization` | 准备或读取授权状态；`OFFERED` 返回冻结患者内容、版本、摘要和有效期；`APPROVED` 返回唯一回执；`RESTRICTED` 不返回内容 |
| `POST /diagnosis-tasks/{id}/save-authorization/approve` | 显式批准，提交 `{authorizationId, expectedTaskVersion, expectedDraftVersion, expectedEvidenceVersion, expectedContentDigest}` |
