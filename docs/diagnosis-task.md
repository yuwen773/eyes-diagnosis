# 患者眼底图片分析任务

此入口与现有同步诊断、聊天入口独立，不创建正式诊断记录，也不向患者展示预测或未审核的内容。

- `POST /api/diagnosis-tasks`：已登录用户提交 multipart `file` 和客户端生成的 `idempotencyKey`。键限 1–128 个 ASCII 字母、数字或 `._~-`。同一用户使用同一键和相同图片请求会获得原任务；请求不同返回 HTTP 409。
- `GET /api/diagnosis-tasks`：返回当前用户最近 50 个任务的安全状态；`GET /api/diagnosis-tasks/{id}` 只允许读取当前用户的任务。状态为 `PROCESSING`、`WAITING_REVIEW` 或 `RESTRICTED`，未知内部状态按受限处理。

任务使用 MySQL 租约和递增令牌协调 Java 进程内的调度。每次调用 Python 前先提交一次调用额度，最多两次；无法确定请求是否已发出的中断也消耗额度。重启可在租约到期后接管，但 Python 计算可能重复，不能视为 exactly-once。持久化快照由 Java 绑定任务、用户、对象版本和图片 SHA-256；当前 gRPC 协议不回传这些身份字段。快照仅供后续受控流程使用，不是患者结果或正式记录。

新输入使用独立 `diagnosis-task/` 对象前缀。COS 必须提供可读取的版本 ID；无版本、指定版本不可读或摘要不符会进入受限状态，不回退读取普通 key。COS 上传和 MySQL 登记不在同一事务：登记失败或中途崩溃可能遗留孤儿对象，当前不自动删除。后续 MinIO 迁移及存储生命周期工作须另行设计孤儿识别、宽限期和引用复查；聊天图片清理器不处理该前缀。

当前 Python 服务可能返回 OOD 未评估；任务保留绑定输入的内部快照并显示受限，不视为可发布结果。真实 COS 版本配置、真实 Python、浏览器和临床验收需要分别执行并记录，隔离替身测试不能替代它们。
